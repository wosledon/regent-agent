# ADR-0013：外部能力采用可插拔适配，本地模式为默认

- 状态：Accepted
- 日期：2026-11-24
- 范围：Provider、模型目录、存储、密钥库、外部身份、可观测性、审计锚定、备份与部署组件

## 背景

仓库已经具备可运行的本地实现，但真实 Provider、Postgres/RustFS、远程身份、OTLP/Elastic、外部锚定和异地备份仍直接散落在入口或静态调用中。需要在不连接、不调试真实组件的前提下，把这些能力做成可配置、可替换的适配器，并保留本地开发与测试路径。

## 决策

1. 业务模块依赖稳定端口，组合根根据配置选择本地或远程实现。
2. 默认配置使用本地实现；远程适配配置不完整时快速失败，不静默回退。
3. OpenAI/Anthropic 使用各自原生 HTTP 协议，不做跨协议 DTO 转换。
4. 对象存储端口只表达字节上传/读取，生产适配直接使用 S3 SDK/RustFS，不增加业务存储抽象。
5. 外部身份、可观测性、审计锚定和备份目标通过独立端口接入，禁止外部故障阻塞核心业务或扩大权限。
6. 本次实现适配器和选择逻辑，不连接或调试真实远程组件；生产目标仍按 ADR-0003、0004、0005 执行。

## 结果

- 本地模式继续可独立运行和测试。
- 远程能力可以在不修改业务模块的情况下启用。
- 配置、协议、超时、取消、重试、脱敏和失败语义集中到适配边界。
- 需要维护更多适配器和配置测试，但能明确区分本地验收与生产能力。

## 未采用

- 为每个实体或外部服务建立通用插件框架：变化点不足，复杂度过高。
- 在领域服务中直接读取配置或创建 HTTP/S3 客户端：破坏依赖方向和可测试性。
- 静默回退到本地实现：会掩盖配置错误并造成错误的数据权威源。
- 用统一 DTO 转换 OpenAI/Anthropic：违反原生 Schema 与错误语义要求。
