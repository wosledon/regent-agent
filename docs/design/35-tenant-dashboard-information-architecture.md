# 35 租户仪表盘信息架构

- 版本：v0.1（待评审）
- 范围：Boss 首屏、两级导航、项目健康、行动中心、下钻、新鲜度和权限
- 对应需求：FR-019、FR-078、BR-118、BR-119、BR-120
- 对应缺口：G-49

## 1. 定位

- Tenant Dashboard 服务租户股东和管理者。
- 首屏用于快速判断公司健康、风险和待决策事项。
- 仪表盘不是运营后台，也不是原始日志浏览器。
- 升级队列仍是人类最终决策入口。
- 语言、时区和格式规则由 Q-040 定义；完整无障碍支持后置。

## 2. Boss 首屏

```text
公司状态条
├─ 当前目标、运行状态、最后更新时间
├─ 待我处理
├─ 项目健康
├─ 预算与成本
├─ 组织与产能
├─ 风险与审计
└─ 最近决策
```

首屏必须回答：

1. 公司现在健康吗？
2. 哪些项目有风险或被阻塞？
3. 钱花到哪里、是否超预算？
4. 组织和产能是否异常？
5. 哪些事情必须由 Boss 处理？

不进入首屏：

- 全部日常任务。
- 全部消息。
- 原始日志和 Trace。
- 无优先级的通知流。
- 没有行动含义的图表。

## 3. 首屏卡片

| 卡片 | 必需字段 |
|---|---|
| 公司状态 | 当前目标、运行状态、关键里程碑、更新时间 |
| 待我处理 | 事项数量、最高严重度、最早超时、负责人 |
| 项目健康 | 项目数、风险项目、阻塞项目、下一里程碑 |
| 预算成本 | 已用、预算、燃烧速率、预测、未知价格、Unallocated 和异常数 |
| 组织产能 | 在岗、可用、过载、异常、招聘中 |
| 风险审计 | 未关闭事件、审计验证、删除和许可异常 |
| 最近决策 | 决定、理由摘要、结果、关联证据 |

每张卡片必须支持下钻，不能只显示汇总数字。

## 4. 导航

最多两级：

1. 总览。
2. 项目与交付。
3. 组织与员工。
4. 消息与协作。
5. 模型与预算。
6. 知识与公司志。
7. 治理与升级。
8. 设置。

治理与升级包括：

- 升级队列。
- 行动中心。
- 安全事件。
- 审计与合规。
- 人事决策事后审查。

运营平台页面不进入租户导航。租户与运营界面保持不同认证 audience、路由和审计。

## 5. 项目阶段与健康

### 5.1 工作流阶段

```text
BriefReady → Approved → Building → Verifying → Releasing → Live → Iterating
```

阶段由项目状态机维护。

### 5.2 健康状态

```text
OnTrack
AtRisk
Blocked
PendingAcceptance
Live
Failed
```

- `OnTrack`：当前门禁和里程碑在阈值内。
- `AtRisk`：预测将逾期、预算或质量接近阈值。
- `Blocked`：存在未解决依赖、审批、资源或安全阻断。
- `PendingAcceptance`：交付完成，等待独立验收。
- `Live`：已发布且运行健康。
- `Failed`：关键门禁失败或项目终止。

健康状态由确定性规则计算，LLM 不得直接修改。

## 6. 健康计算

输入：

- 里程碑和截止时间。
- 任务状态与依赖。
- 验收和发布门禁。
- 预算与实际燃烧速率。
- 员工和 Runner 可用性。
- 安全事件和升级事项。
- 数据新鲜度。

规则：

- 硬阻断优先于其他状态。
- PendingAcceptance 优先于一般风险。
- Live 仅表示已发布且当前健康，不覆盖活跃安全事件。
- 数据过期时显示 `Unknown` 或 `Stale`，不能默认 OnTrack。
- 每次计算保存规则版本和输入快照引用。

## 7. 行动中心

统一聚合：

- 升级事项。
- L1～L3 告警。
- 安全事件。
- 预算预警。
- 发布阻断。
- 模型不可用。
- 删除和审计异常。
- 许可证和供应链风险。

ActionCenterItem 字段：

```text
id
tenant_id
source_type
source_id
severity
title
owner_id
created_at
sla_due_at
requires_boss_decision
next_action
evidence_ref
dedupe_key
status
```

规则：

- 同一根因使用 dedupe_key 合并。
- 严重程度使用 Critical、High、Medium、Low。
- 必须显示负责人、等待时间、下一步和是否需 Boss 决策。
- 升级事项还显示缺席协商状态、审批委托链和 SLA 剩余时间。
- Ack 不改变源事件状态，只记录处置责任。
- 关闭必须引用源事件结果。
- 行动中心不能绕过原审批和审计。

## 8. 告警呈现

| 等级 | 默认行为 |
|---|---|
| Critical | 首屏顶部、行动中心置顶、立即提示 |
| High | 待我处理和行动中心显示 |
| Medium | 行动中心显示，不默认打断 |
| Low | 归入通知和趋势 |

- 去重、分组和抑制与后端告警规则一致。
- Q-045 已确认只实现站内通知中心，外部渠道后置；本设计定义站内呈现和行动入口。

## 9. 下钻

卡片下钻必须到达：

- 项目状态机和门禁证据。
- 账本明细和价格快照。
- 员工状态与原因归因。
- 升级事项的选项和影响。
- 安全事件时间线。
- 审计验证和删除证明。

下钻页面保留原始筛选和返回位置。

## 10. 数据新鲜度

- 每张卡片显示数据时间和采集延迟。
- 超过阈值标记 `Stale`。
- 权威源不可用时显示 `Unknown`。
- Stale 和 Unknown 不得使用绿色健康状态。
- SignalR 只推送增量，断线后重新拉取快照。
- 投影滞后不改变业务权威状态。

## 11. Butler 摘要

- Butler 可以解释状态、汇总风险和生成下一步建议。
- 摘要必须引用确定性卡片和证据。
- 摘要不能修改状态、关闭告警或替代审批。
- 当数据 Stale 或 Unknown 时，Butler 必须明确说明不确定性。

## 11.1 组织协作可视化

- 组织与员工导航提供“组织协作可视化”入口，与员工列表、岗位管理并列。
- 工作台支持办公室、组织图、协作网络、过程时间线四种等价视图，切换不改变筛选和选中对象。
- 办公室以岗位/项目房间和会议群呈现员工工作；组织图呈现汇报树；网络呈现员工协作、项目工作和群成员关系；时间线聚合工作、消息与审计。
- 每个节点下钻显示来源事件、证据和审计哈希；群聊节点显示成员、消息、回复、@ 与证据，可直接进入消息页。
- 可视化是只读投影，不替代项目、任务、消息或审计权威记录；Stale/Unknown 不得显示为健康绿色状态。

## 12. 权限

- 导航和卡片由服务端按 Capability 过滤。
- API 每次重新校验租户、成员身份和数据范围。
- 菜单隐藏不是安全边界。
- 个人绩效、私人记忆和秘密不进入通用卡片。
- 人类事后审查页面只显示授权范围。

## 13. 状态与反馈

必须覆盖：

- 首次使用空状态。
- 无项目、无员工、无告警。
- 加载中。
- 投影延迟。
- 数据源失败。
- 权限不足。
- 操作成功和失败。
- 超时和过期。

空状态必须解释下一步，不显示误导性的零风险。

## 14. 响应式与可访问性

- 移动端支持首屏查看、告警确认和升级审批。
- 复杂组织和项目编辑以桌面为主。
- 完整键盘、屏幕阅读器和 WCAG 2.2 AA 专项支持按 Q-040 后置。
- 当前不将无障碍作为 MVP 发布门禁，也不宣称 WCAG 合规。
- 后续实施时状态必须同时提供文本和图标，不能只依赖颜色。

## 15. 性能

- 首屏使用服务端只读投影，不直接查询原始日志。
- 单页首屏初始加载 P95 目标 ≤2 秒。
- 卡片独立加载，单卡片失败不阻塞整页。
- 分页和虚拟化用于项目、员工和行动中心列表。
- SignalR 推送节流，避免高频状态造成界面抖动。

## 16. API 与事件

- `GET /dashboard/summary`
- `GET /dashboard/projects`
- `GET /dashboard/action-center`
- `GET /dashboard/cards/{card_id}`
- `POST /dashboard/action-center/{id}/ack`

事件：

- `DashboardProjectionUpdated`
- `ProjectHealthChanged`
- `ActionCenterItemOpened`
- `ActionCenterItemMerged`
- `ActionCenterItemResolved`

| 行动中心来源覆盖率 | 100% |

| 状态新鲜度异常数 | 0 |

## 18. 测试场景

1. 首屏包含五类关键问题。
2. 日常任务和原始日志不进入首屏。
3. 项目阶段和健康状态分别显示。
4. 硬阻断优先于一般风险。
5. 数据过期时不显示 OnTrack。
6. 行动中心聚合所有约定来源。
7. 同一根因告警去重。
8. 卡片可下钻到证据。
9. Butler 摘要不能修改状态。
10. 无权限用户看不到他人绩效和私有记忆。
11. 隐藏菜单后直接调用 API 仍被拒绝。
12. SignalR 断线后可恢复快照。
13. 单卡片失败不阻塞整页。
14. 移动端可以查看和审批。
15. 无障碍专项后置，不阻塞 MVP 发布。

## 19. 验收场景

1. Boss 首屏能快速回答健康、风险、预算、组织和待决策。
2. 导航最多两级。
3. 项目健康由确定性规则计算。
4. 行动中心完整、去重且可追踪。
5. 每张关键卡片可下钻。
6. 数据时间和新鲜度清晰。
7. Butler 不覆盖权威状态。
8. 租户权限在服务端强制执行。
9. 运营后台不进入租户导航。
10. 空状态、失败状态和 Stale 状态不误导用户。
