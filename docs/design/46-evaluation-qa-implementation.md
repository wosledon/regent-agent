# 46 模型评测 QA 实施细则

- 版本：v0.1（待评审）
- 范围：密封集、污染检测、Judge 员工、校准、重复、统计门槛和失败处置
- 对应需求：FR-090、BR-161、BR-162、BR-163、BR-164、BR-165
- 对应缺口：G-61

## 1. 目标

- 让模型评测可复现、防污染、可校准、有统计门槛。
- Judge 使用正式员工运行时，但保持独立实例和上下文。
- 评测失败不自动换模型、绑定员工或触发处罚。
- 本细则是 [14 模型评测与回归](./14-model-evaluation-and-regression.md) 的执行补充。

## 2. 数据集分区

| 分区 | 用途 | 访问 |
|---|---|---|
| development | 调试 Prompt、工具和评分 | 授权评测开发者 |
| calibration | Judge 和 Rubric 校准 | 授权评估者 |
| holdout | 正式成绩 | 仅评测服务 |

- 每个案例标记 `split`，版本发布后不可移动。
- holdout 不进入员工上下文、普通 API、日志、记忆、Skill、Prompt 或向量索引。
- 标准答案和 Judge 提示词与候选模型隔离。
- 每个租户使用独立 canary 标记检测泄漏。
- 每 6 个月至少轮换 20% holdout；污染案例立即隔离并替换。

## 3. 污染检测

发布前和每次正式评测执行：

1. 精确内容 hash 重复。
2. 规范化文本近似重复，相似度阈值 `0.92`。
3. 已知公开基准污染记录。
4. canary 标记出现在 Prompt、输出、日志或记忆。
5. development、calibration、holdout 和跨租户数据交叉泄漏。

处置：

- 案例进入 `ContaminationFinding`。
- 隔离案例或整个数据集版本。
- 受影响 EvaluationRun 标记 `Quarantined`。
- 人工复核后生成新版本，不静默删除或改写。
- 误报保留检测记录和理由。

## 4. Judge 员工

- Judge 是具备 `evaluation.judge` 能力的正式员工。
- 使用独立 EmployeeRuntime 和评测任务，不占主控上下文。
- 优先绑定与候选员工不同的 Provider、模型或版本。
- 只配置一个模型时，允许同模型不同运行时。
- 禁止评审自己的产出或自己参与的任务。
- 禁止读取候选员工的记忆、聊天、工作区和私有上下文。
- 禁止读取密封题、标准答案和 Judge 提示词。
- 主控可以选派 Judge 和查看汇总，不能直接充当评测现场。

`JudgeAssignment.independence`：

```text
DifferentModel
SameModelDifferentRuntime
```

`SameModelDifferentRuntime` 标记为 `SameModelJudge`，降低结论置信度；招聘、调岗和绩效等高影响场景必须增加人工复核。

## 5. Judge 校准

每个 Judge 版本首次使用前：

- 两名独立人工评分者盲评。
- 样本至少 100 条或 20% 案例，取较大值。
- 覆盖各能力维度、语言和难度。
- 人工先独立评分，再协商分歧。
- 记录一致率和加权 Cohen’s κ。

门槛：

| 指标 | 门槛 |
|---|---:|
| Judge 与人工一致率 | ≥85% |
| 加权 Cohen’s κ | ≥0.70 |

- 不达标时 Judge 隔离，主观维度转人工评分。
- 每月重新抽检。
- Judge 模型、Prompt、示例或 Rubric 变化必须重新校准。
- Judge 调用失败或结果不可复现时进入复核，不默认通过。

## 6. 样本与重复

| 项目 | 最小规模 |
|---|---:|
| 核心集 | 100 条 |
| 安全/租户隔离集 | 50 条 |
| 单能力维度 | 30 条 |
| 每日 canary | 20 条 |

- 每个案例固定 seed 连续运行 3 次。
- 核心和安全案例必须 `3/3` 通过。
- 其他案例至少 `2/3` 通过才计为通过。
- 环境故障与能力失败分开，最多重试 2 次。
- 有效样本不足时结论为 `Inconclusive`。
- 重复结果用于计算 Flaky 率，不能挑选最好一次作为正式结果。

## 7. 质量与统计门槛

| 指标 | 门槛 |
|---|---:|
| 安全、租户隔离、核心案例 | 100% |
| P0/P1 失败 | 0 |
| 整体通过率 | ≥80% |
| 整体 Wilson 95% 下界 | ≥75% |
| 单能力维度 | ≥70% |
| 单维度 Wilson 95% 下界 | ≥65% |
| 关键指标相对基线下降 | ≤5 个百分点 |
| 单维度相对基线下降 | ≤10 个百分点 |

- 基线比较使用配对 McNemar 精确检验，单侧 α=0.05。
- Wilson 区间、样本量、波动和不稳定案例写入报告。
- 硬失败不能被总分、权重或统计显著性抵消。
- 统计策略版本化，运行前冻结。

## 8. 评分顺序

```text
确定性测试
  → 规则评分
  → Judge 员工评分
  → 人工抽检/校准
  → 统计门槛
```

- 确定性测试不使用 Judge。
- Judge 只处理主观维度。
- Judge 评分理由、版本和输入 hash 全部记录。
- Judge 不能看到其他 Judge 的结论，避免锚定。
- 评分规则在运行前冻结，不得看到结果后修改。

## 9. 结果状态

| 状态 | 含义 | 使用 |
|---|---|---|
| Approved | 门槛通过 | 可供新绑定评审 |
| Rejected | 明确未达标 | 禁止新绑定 |
| Quarantined | 污染、Judge 失效或安全失败 | 禁止使用 |
| Inconclusive | 样本不足或环境失败 | 补测后再判断 |

- 安全案例任何一次失败立即 Quarantine。
- Judge 校准失效时相关主观评分 Quarantined。
- 污染数据集版本相关运行全部 Quarantined。
- Approved 不自动绑定员工。
- 在途任务不自动换模型。
- 失败不自动触发员工处罚。

## 10. 复测

- 复测失败案例和 20% 相邻回归。
- 安全集始终全量复测。
- 使用相同或更严格门槛。
- 数据集、Rubric 或 Judge 版本变化生成新 EvaluationRun。
- 旧结果不能直接复用。
- 复测保留原始失败和两次结果，不覆盖历史。

## 11. 实体

- `JudgeAssignment`：Judge 员工、模型绑定和独立性。
- `JudgeCalibration`：人工样本、一致率、κ 和状态。
- `ContaminationFinding`：检测器、相似度、隔离和解决。
- `StatisticalGate`：估计值、置信区间、检验和结果。
- `EvaluationRetest`：失败案例、相邻回归和安全复测范围。

## 12. 指标

| 指标 | 目标 |
|---|---:|
| 污染事件 | 0 |
| Judge 人工一致率 | ≥85% |
| Judge 加权 κ | ≥0.70 |
| Flaky 案例率 | ≤5% |
| Inconclusive 比例 | ≤5% |
| 安全集复测覆盖率 | 100% |
| Judge 自评事件 | 0 |
| 密封集泄漏事件 | 0 |

## 13. 测试场景

1. development 案例不能计入正式成绩。
2. holdout 不能通过普通员工 Tool 读取。
3. canary 出现在生产上下文时触发污染事件。
4. 近似重复 0.92 被隔离。
5. 误报保留检测和人工解决记录。
6. Judge 是正式员工和独立运行时。
7. 只有一个模型时允许同模型不同运行时。
8. Judge 不能评审自己的产出。
9. Judge 不能读取候选员工记忆或聊天。
10. Judge 校准样本少于 100 条或 20% 时拒绝激活。
11. 一致率低于 85% 时 Judge 隔离。
12. κ 低于 0.70 时主观维度转人工。
13. Judge 版本变化后重新校准。
14. 核心样本少于 100 条时 Inconclusive。
15. 安全样本少于 50 条时 Inconclusive。
16. 核心或安全案例不是 3/3 时失败。
17. 其他案例 2/3 才计通过。
18. 环境故障不计为能力失败。
19. 有效样本不足时 Inconclusive。
20. Wilson 下界不足时不能 Approved。
21. McNemar 显示显著下降时不能 Approved。
22. 安全失败立即 Quarantined。
23. 复测包含失败案例和 20% 相邻回归。
24. 安全复测始终全量。
25. 失败不自动换模型或处罚员工。

## 14. 验收场景

1. 密封集和 canary 泄漏可检测、可隔离。
2. Judge 是独立员工运行时，模型可同但上下文不可共享。
3. Judge 校准有样本、一致率和 κ 门槛。
4. 最小样本、3 次重复和统计门槛可复现。
5. 四态结果和复测范围明确。
6. 污染、失败和不稳定结果不会被静默当作通过。
