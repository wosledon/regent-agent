# 02 运行时可靠性与持久化

- 版本：v0.1（待评审）
- 范围：调度、租约、消息、故障恢复、工作区、成果和降级
- 对应缺口：G-05、G-06、G-07、G-15、G-16

## 1. 核心不变量

1. Runner 是计算宿主，不是业务状态的事实来源。
2. 任务可重复领取，但同一幂等键不得产生重复业务副作用。
3. 旧 worker 的迟到结果不能覆盖新 worker 的结果。
4. 已确认的任务状态、成果和账本事件不依赖 Runner 本地磁盘。
5. 控制面不可用时，Runner 只做有界重试，不把本地缓冲当作可靠存储。
6. 工作区和成果存储独立于 Runner 生命周期，可被其他 Runner 重新挂载。

## 2. 任务调度与租约

### 2.1 任务记录

```text
Task:
  id, tenant_id, employee_id, type, state
  priority, available_at, attempt, max_attempts
  idempotency_key, payload_schema_version
  required_capabilities, required_workspace_id
  lease_token, lease_owner, lease_expires_at
  last_error, next_retry_at, created_at, completed_at
```

### 2.2 领取算法

控制面在单个数据库事务中完成：

1. 查询当前 Runner 能力可执行、租户公平调度允许的 `Pending` 任务。
2. 锁定任务行，递增 `attempt` 和 `lease_token`。
3. 设置 `state=Assigned`、`lease_owner=runner_id`、`lease_expires_at=now+60s`。
4. 创建员工 assignment token，返回任务、工作区和租约信息。
5. Runner 在 10 秒内确认开始；未确认则租约过期并重新排队。

公平调度使用租户级活动任务配额和加权轮询，单租户不能占满所有重任务槽；有其他租户等待时，单租户连续占用共享槽位最多 3 次后让出。容量和 noisy neighbor 门槛见 [44 容量与性能基线](./44-capacity-and-performance-baseline.md)。

### 2.3 续租与完成

- Runner 每 15 秒续租一次；续租必须携带当前 `lease_token`。
- 连续两次续租失败即停止接收新动作，并在安全点结束当前任务。
- 完成、失败、取消必须携带 `lease_token` 和 `Idempotency-Key`。
- 完成请求先验证成果哈希和报告，再提交状态、Outbox 和审计。
- 旧 token 提交返回 `409 STALE_LEASE`。

### 2.4 孤儿与重试

- 调度器每 5 秒扫描过期租约。
- `Assigned/Running` 租约过期转 `Pending`，`next_retry_at` 使用指数退避。
- 默认最多 3 次尝试；可重试错误包括超时、依赖不可用、worker 崩溃。
- 参数错误、策略拒绝、内容违规不自动重试，直接进入 `Failed` 并告警。
- 超过最大尝试次数的任务进入死信列表，由主控、具备任务决策能力的岗位或股东决定重开或终止。

### 2.5 副作用保护

所有外部动作必须满足以下至少一项：

- 使用业务幂等键，如 `publish:{project}:{release}:{version}`。
- 使用租约 fencing token 作为条件写入。
- 通过升级审批的 `action_hash` 绑定参数。
- 对不可撤销动作先写意图日志，执行后写结果；崩溃后由补偿器核对。

### 2.6 公司作息调度

- 公司全天 24 小时可配置，普通任务只在用户禁用窗口进入 Scheduled。
- 可延期任务可利用 CostWindow，折扣未知时按有效价格记账。
- 到达禁用窗口或排班结束时保存 TaskCheckpoint、释放租约并标记 DeferredUntil。
- P0、安全事件、硬预算和密钥风险按 WakePolicy 紧急唤醒。
- 紧急唤醒不扩大权限，临时加班使用限时 ScheduleOverride。
- 用户禁用窗口和休息时间不计员工可用率分母，详见 [38 公司作息与调度](./38-company-work-schedule-and-dispatch.md)。

## 3. 消息总线

### 3.1 消息表

```text
messages:
  id UUID
  tenant_id UUID NOT NULL
  seq BIGINT NOT NULL
  to_id UUID NOT NULL
  type VARCHAR NOT NULL
  payload JSONB NOT NULL
  schema_version INT NOT NULL
  idempotency_key VARCHAR NOT NULL
  created_at TIMESTAMPTZ NOT NULL

UNIQUE(tenant_id, seq)
UNIQUE(tenant_id, idempotency_key)
```

- `seq` 在租户内单调递增，避免跨租户泄露顺序和全局写竞争。
- 广播消息使用 `to_id` 的保留值 `role:ceo` 或 `company:all`，仍带 `tenant_id`。
- 消息载荷不得包含密钥、原始 Authorization 头或无限增长的日志。

### 3.2 投递语义

- 生产者和消费者均使用 Outbox/Inbox 模式。
- 消费顺序只保证同一 `to_id` 内有序，不保证跨员工全局有序。
- 消费者在事务中写入 inbox 记录、更新 cursor、执行业务状态变更。
- 同一消息重复投递时，`inbox_messages(consumer_id, message_id)` 唯一约束保证只处理一次。
- Ack 在业务事务提交后才发送；进程崩溃会重读。

### 3.3 毒消息与保留

- 同一消息连续失败 5 次进入死信队列，不再阻塞后续消息。
- 控制面记录失败原因并生成 L2 告警；涉及红线内容时同时生成升级事项。
- 消息默认在线保留 90 天，之后按月归档；审计事件按 7 年保留类处理。
- cursor 不得指向已删除或已归档数据；归档后消费者只能从新 cursor 开始。
- 重要结论必须提升为 Decision 或知识库版本，不能只依赖聊天归档。

## 4. Runner 无状态的精确定义

Runner 不得持久化以下业务事实：

- 员工生命周期状态、任务状态、租约、组织关系。
- 唯一成本记录、审批状态、模型密钥引用。
- 唯一成果副本、项目决策、公司记忆。

Runner 可以拥有的临时状态：

- 当前进程内的 Channel 队列。
- 未确认网络请求的内存重试。
- 容器进程、临时目录和缓存。

这些临时状态丢失后，系统必须通过租约过期、幂等重试和持久化成果恢复，不依赖本地文件找回。

## 5. 工作区与成果持久化

### 5.1 工作区键

统一使用：

```text
WorkspaceKey = (tenant_id, project_id, repo_key, toolchain)
```

共享代码库和工具链决定缓存键；每个 TaskRun 使用独立 worktree：

```text
TaskWorkspaceKey = (tenant_id, project_id, repo_key, toolchain, task_id)
```

### 5.2 存储分层

| 层 | 内容 | 生命周期 |
|---|---|---|
| Postgres | 工作区元数据、Git 引用、分配、状态、checksum | 永久/归档 |
| RustFS | Git Bundle、工作区快照、简报、报告、发布包 | 按保留策略 |
| Runner 本地/容器目录 | 当前 worktree、临时下载、未确认缓存 | 可随时丢弃 |
| 本地共享缓存 | 裸仓库和依赖缓存 | 性能优化，不是真相 |

Runner 只拥有活动工作目录，不拥有工作区生命周期；已确认快照和成果必须进入 RustFS。

### 5.3 分配与迁移

- 一个 TaskRun 一个独立本地 worktree，禁止并发写同一目录。
- 共享裸仓库和依赖缓存可以减少重复下载，但不得跨租户。
- Runner 下线后旧租约失效，新 Runner 从 RustFS 恢复最近快照。
- 工作目录可以随 Runner 丢失，Postgres 引用和 RustFS 快照保持不变。
- 路径由服务端生成，容器只挂载本任务目录。

### 5.4 成果提交协议

1. Runner 在临时路径生成成果。
2. 计算 SHA-256、大小和 MIME 类型。
3. Postgres 创建 `PendingUpload` 对象记录。
4. 上传 RustFS 并校验 key、大小和 checksum。
5. Postgres 标记 `Ready`，任务完成事务引用对象和哈希。
6. Ready 对象不可覆盖；孤儿对象由后台回收器清理。

代码快照和报告统一进入 RustFS，元数据和 Git 引用进入 Postgres。详见 [15 数据 Schema 与事务边界](./15-data-schema-and-transactions.md)。

## 6. ControllerRuntime 与 EmployeeRuntime

### 6.1 ControllerRuntime

```text
while not stopping:
    state = await controlPlane.RestoreCompanyStateAsync()
    plan = await controller.ReasonAsync(state, charter, policy)
    changes = await controlPlane.ApplyOrgPlanAsync(plan)
    tasks = await controlPlane.CreateTasksAsync(plan)
    await controlPlane.RecordDecisionAsync(plan, changes, tasks)
```

- 主控循环只产生组织计划、决策和任务，不直接持有唯一业务状态。
- 主控自建岗位激活后，岗位任务通过普通 EmployeeRuntime 执行。
- 主控未自建岗位时只能执行 bootstrap 和组织修复，不能领取普通员工任务。
- 继任和休眠使用控制面状态机，不依赖 Runner 本地内存。

### 6.2 EmployeeRuntime 主循环

```text
while not stopping:
    item = await inbox.ReadAsync(cancellationToken)
    lease = await controlPlane.EnsureLeaseAsync(item)
    if lease is null:
        continue

    context = await controlPlane.RestoreContextAsync(item)
    result = await agent.RunAsync(context, tools, cancellationToken)

    artifacts = await artifactStore.CommitAsync(result.Artifacts)
    await controlPlane.CompleteAsync(item, lease.Token, artifacts, usage)
```

- 主循环串行处理自身动作，避免同一员工并发修改同一上下文。
- `tools` 来自控制面 `/tools/discover`，包含当前 Tool Profile 的 Primary 完整 Schema 和 Auxiliary 简介。
- Auxiliary 通过 `/tools/expand` 或 `/tools/activate` 展开，激活不能突破 Authorized Tools。
- 每次 Tool Call 携带 `tool_call_id`、profile_id、授权版本和可选 activation_id；Runner 不缓存永久权限。
- 收到授权、画像或撤销事件后刷新 Tool 列表；在途调用由 PEP 按事务版本处理。
- 不同员工可以并行，但共享工作区冲突由 Git/worktree 和合并门禁处理。
- 休眠时不持有任务租约；唤醒只由新任务或消息触发，并重新获取可见 Tool。

### 6.3 WorkflowRun 执行

- Run 创建时固定 `workflow_version_id`，后续版本不影响在途运行。
- 每个步骤创建普通 Task，由控制面按能力分派。
- 步骤 Tool 调用仍走 Tool Registry/PEP，工作流不额外授权；步骤可切换 Tool Profile，但不能扩大权限上限。
- 步骤输出提交为 Artifact，门禁通过后进入下一步。
- 失败按步骤策略重试；超时、成本超限或能力缺失时暂停并告警。
- 取消运行不删除已提交 Artifact 和审计。

### 6.4 记忆索引与维护

- 记忆写入先提交 Record/Version 和 Outbox，再由 Worker 异步更新向量、全文和关系索引。
- 衰减、验证过期、冲突检查、合并、归档和清除均由确定性后台任务执行。
- 删除先停止召回，再异步清除索引、缓存和派生内容。
- 索引任务幂等，失败重试并告警。
- Embedding 模型更换时创建新索引，验证通过后再切换。

### 6.5 绩效调度

- 周期评估由调度器按 KPI cadence 触发，主控默认 7 天。
- 事件评估由失败、质量、预算、里程碑等 Outbox 事件触发。
- KPI 计算是确定性程序，LLM 只生成证据摘要和建议。
- 评估使用普通 Task、租约和幂等机制。
- 申诉期间高影响动作保持暂停，复核任务独立分派。

### 6.6 项目工作项调度

- 需求 Ready、任务认领、评审请求、缺陷复测和项目报告通过 Outbox 事件驱动。
- 任务认领使用事务和条件更新，重复认领返回首次结果。
- 执行任务复用普通 Task lease/fencing，项目工作项引用运行时 task_id。
- 认领前计算 TaskWeight、TaskRequirement、CapabilityAssessment 和 WipCapacity 版本；版本变化后重新评分。
- 认领邀请默认 15 分钟有效，拒绝或超时后推荐下一候选人，不静默强派。
- 工作项关闭前由控制面校验 DoneEvidence；证据不足时保持 InReview 并返回缺失项。
- 工作流步骤可以推进 Task，但不能跳过就绪、评审和验收门禁。
- DecompositionPlan 通过校验和审批后才创建 Ready Task；批准后幂等投影为运行时 `TaskRecord`，重复同步不重复建任务或审计。
- 运行时认领和完成分别回写交付任务为 `Claimed` 和 `ReadyForReview`；提交、独立评审和 DoneEvidence 继续推进同一工作项。
- 重拆使用增量事件，不改写旧任务历史。
- 评审按 quorum 分派，Ack、完成和 Debate 截止时间由调度器跟踪；超时改派或升级，不自动通过。
- 调度使用 TaskTypeDefinition 版本选择能力、Tool Profile、权重和 Done 模板；版本变化后重新评估在途任务。
- 项目暂停或员工离职时，任务按策略释放、阻塞或重新分配。
- Runner 重启后从控制面恢复工作项状态和事件，不依赖本地队列。

### 6.7 通信路由

- Runner 获取当前 CommunicationProfile 和组织版本，发送前由控制面重新计算路由。
- 组织、标签或项目成员变化后通过 Outbox 发布失效事件，Runner 刷新联系人。
- 路由事件至少投递一次，重复事件不会重复创建授权。
- 路由失败不产生消息副作用；ControllerFallback 创建普通 Task。
- 路由缓存必须包含 org_version，不能跨组织版本复用。

### 6.8 Agent 上下文与缓存

- 上下文由系统与岗位规则、TaskCheckpoint、当前工作上下文和长期记忆检索组成。
- 输入预算达到 70% 时准备压缩；输出预留 20%，安全余量 5%。
- 压缩必须保留目标、约束、决策、失败、反证、证据和下一步。
- 超长工具结果写入 RustFS，模型只接收摘要、关键片段和引用。
- 稳定前缀顺序为系统规则 → Charter/岗位 → Tool Schema；动态检索和工具片段放在后缀。
- 对话采用追加方式，不重写已缓存历史；跨任务只复用稳定前缀。
- Charter、岗位、权限或安全策略变化时主动失效相关缓存。
- Runner 崩溃后从 TaskCheckpoint 和事件恢复，不依赖模型记忆。
- ContextPacket 记录版本、引用、排除项、token、压缩和缓存信息。
- TaskRun 固定 PromptBundle；提示词或技能升级只影响新任务，回滚不中断在途任务。

### 6.9 Agent 工具循环

- 单片段默认最多 20 个模型轮次、40 次 Tool 调用、3 次连续失败和 3 轮无进展。
- 到软限制后保存 TaskCheckpoint、释放租约并立即创建下一段，不终止整个任务。
- 调用指纹由工具、规范化参数和资源版本组成；重复两次后拦截第三次。
- 连续无进展时重新规划、拆分、内部求助或升级。
- 部分成功先保存结果，只重试失败且幂等的部分；无法确认时标记 `OutcomeUnknown`。
- 取消后不发起新调用，在途外部写入必须核对。
- 任务成本 50% 预警、80% 通知直接 Leader、100% 暂停并逐级评审。
- 模型和推理强度绑定员工，任务中不可临时更换；不合理时调岗或拆分。
- 成本评审沿管理链逐级上报，Controller 只接收管理链无法解决的事项。

### 6.10 聊天与协作投递

- 聊天消息以控制面消息表为权威源，SignalR 只负责实时推送。
- 普通消息进入队列或摘要，P0/P1 和 @ 才优先唤醒员工。
- 消息至少投递一次，Inbox 去重，Ack 与完成分离。
- 委派和交接使用条件更新，确认前不改变所有权。
- 聊天召回先权限过滤，再按来源、时间、相关度和验证程度加权。
- 默认披露摘要和相关消息，完整线程按需展开。

### 6.11 模型恢复与员工状态

- 模型、版本和推理强度绑定员工，TaskRun 固定；只允许同模型重试或同版本端点切换。
- 连续 2 次失败或 5 分钟持续不可用由算法生成 ModelUnavailableEvent 并上报直接 Leader。
- 员工状态由 Gateway、ControlPlane 和 Sentinel 维护，LLM 不得自行修改。
- `Busy` 不接新任务，`RateLimited` 冷却，`Degraded` 降风险，`Unavailable` 暂停并保存检查点。
- `PendingReview` 等待 Leader；`Frozen/Terminated` 不接新任务。
- 状态事件记录 reason_code 和归因，KPI 只统计员工可避免部分。

### 6.12 models.dev 目录恢复

- 每日同步失败时保留最近有效 CatalogSnapshot，并标记 Stale。
- 手工补价和 models.dev 自动覆盖都生成新版本，不修改历史值。
- 目录校验失败时不发布部分数据；价格缺失进入 Unpriced 和对账队列。
- 目录恢复后重新计算新请求的有效价格与档位，不追溯历史任务。

### 6.13 部署 Drain 与版本兼容

- 升级前 Runner 停止新认领，等待在途任务到检查点。
- Runner 注册声明最低控制面版本，N-2 版本拒绝注册。
- 旧 Runner 只完成已认领任务，新任务只由兼容版本处理。
- 升级中断时保留 PendingUpload 和 Outbox，恢复后继续。
- 应用回滚必须确认数据库仍处于 Expand 且数据兼容。

### 6.14 不可信内容与 TaskGrant

- Runner 接收外部内容时生成 UntrustedContent，保留来源、hash 和 taint。
- Tool 结果经 Schema、大小、清理和风险检测后进入上下文。
- TaskGrant 内不逐步审批；执行层每次 Tool Call 独立校验权限和动作范围。
- 检测误报只隔离来源，不中断员工全部工作。
- 只有越界动作暂停并升级，环境攻击不进入员工故障 KPI。

### 6.15 记忆纠错与影响恢复

- MemoryFinding 高风险 claim 立即停止召回，低风险降权复核。
- CorrectionTask 使用普通租约、WIP 和幂等机制。
- 个人记忆纠错保留原作者 ACL，复核者不成为个人 claim 的所有者；组织记忆仍由独立复核者署名。
- 纠正通过 Outbox 传播，索引、缓存和派生摘要失败可重试。
- 在途任务标记上下文失效并重新检索，已完成工作不自动回滚。

### 6.16 离职、调岗与再入职

- 调岗在同一事务切换任职并重算权限，保留员工运行时和工号。
- 再入职创建新任职周期、会话和凭据，不恢复旧私有记忆。
- 离职立即撤销新调用；Pending/Assigned/InProgress/InReview/Blocked 任务转 `Interrupted`，清除租约所有者、token 和到期时间，并记录中断任务 ID。
- 任务认领排除 terminated 员工，旧 Assignment Token 和旧租约不能继续访问或完成；Token 的 `credential_epoch` 绑定任职周期，离职结束周期后再入职创建新周期，旧 Token 不会恢复。
- Gateway 对每次 Agent 请求都向 ControlPlane 校验 assignment 当前状态，不使用正向授权缓存；终止或任职周期变化在下一个请求即生效。
- 未知 assignee 自动创建 Runner 员工前必须通过租户员工套餐配额；配额不足时任务保持 Pending 并返回冲突，不产生部分员工记录。
- Boss 批准前不执行移除订阅，申诉期间保持暂停。
- 本地工作区在 RustFS 快照确认后清理。

### 6.17 安全事件运行响应

- SEV1 自动冻结受影响 Runner、Tool Profile、制品和会话，不等待逐级审批。
- 安全事件与可靠性事件分开记录，可关联但不能互相覆盖。
- 证据快照在遏制后尽快采集，原始审计和对象不被覆盖。
- 恢复需 IC 批准并完成审计、账本、对象和密钥对账。
- 主控不能关闭事件或删除证据。

### 6.18 账户恢复与会话撤销

- 恢复码在事务内核销，重复提交不产生第二次重置。
- 找回成功通过 Outbox 撤销全部 access/refresh token 家族。
- 撤销失败时保持恢复请求可见并重试，不报告为成功。
- GitHub OAuth 回调失败不创建登录会话。
- 找回异常可关联安全事件，但不记录密码或恢复码。
- 已验证邮箱合并必须在单库事务内完成唯一性检查、身份绑定和审计 Outbox。
- 并发相同邮箱合并只能有一个成功，其他请求返回冲突。
- 未验证邮箱不得进入自动合并路径。

### 6.19 OIDC 登录可靠性

- Discovery、JWKS 和 Token 端点使用有界超时、重试和缓存。
- JWKS 轮换期间保留上一密钥并支持受控刷新。
- 新登录失败不影响已有本地会话和运行任务。
- required 模式 IdP 故障 fail closed，不回退本地密码。
- 配置激活必须原子，失败时保留上一可用版本。
- OIDC 本地会话最长 8 小时，撤销通过现有会话机制执行。

### 6.20 租户切换与所有权变更

- 租户切换必须校验 Active Membership 并原子签发新租户上下文。
- 切换失败不得保留旧 tenant_id 权限或加载目标租户缓存。
- 移除成员时撤销其目标租户会话、委托和访问能力。
- Primary 所有权转让在同一事务内保持唯一 Primary 不变量。
- 最后所有者保护在删除、暂停和降级路径同时生效。
- 代理到期由确定性任务撤销，不依赖用户主动操作。

### 6.21 软删除、恢复与物理清除

- 软删除通过根记录、tombstone 和 Outbox 立即撤销会话、索引和对象访问；租户 ID 按 GUID 值比较，不依赖数据库格式化字符串的大小写。
- 现有 Cookie 会话和 Agent Token 均 fail closed，仅允许租户恢复和会话管理路径。
- 恢复只能在窗口内执行，并原子恢复根记录、成员能力和新会话。
- 物理清除分批幂等，关键步骤失败时保持 Purging 并告警。
- 备份恢复先重放 tombstone，再开放任何查询。
- 法律保留只跳过对应物理清除步骤，不恢复普通访问。
- 清除完成后才写入 purged_at 和最终 DeletionProof。

### 6.22 归档与冷恢复

- 归档任务冻结水位、写对象、校验数量和哈希、提交 manifest 后才退出 Hot。
- 部分上传或校验失败时保留 Hot，不发布半成品清单。
- 冷恢复使用隔离临时前缀和 7 天 TTL。
- 归档任务重跑同一水位必须幂等。
- 归档、恢复和清除均通过 Outbox 跟踪，不依赖单次进程存活。

## 8. 降级与背压

| 依赖 | 降级行为 |
|---|---|
| 控制面 | Runner 停止领新任务，仅续租/重试；缓存只读上下文 |
| 网关 | 员工进入等待；不切换到未授权 provider |
| RustFS | 任务不得标记完成；保留租约并重试上传 |
| 本地工作区丢失 | 从 RustFS 快照恢复；无法恢复时代码任务阻塞 |
| 消息表 | 状态变更仍可提交，但通知延迟；Outbox 保留 |
| 本地模型配置 | 返回明确不支持错误，不创建任务或本地推理资源 |
| 运营平台 | 控制面继续使用最近一次有效配额和策略；暂停/安全封禁事件优先重试，普通配额变更可延迟 |

重任务池并发默认 5；超过时任务保持 `Pending` 并在仪表盘显示排队原因。

### 8.1 运营同步可靠性

- 运营平台与控制面通过幂等事件同步租户状态、套餐、配额和部署策略。
- 控制面保存最近一次成功同步的版本，拒绝乱序事件。
- 暂停、安全封禁和密钥禁用属于高优先级事件，失败时进入重试和告警队列。
- Runner drain 由运营平台下发策略，由控制面执行；运营平台不直接给 Runner 派任务。
- 监控指标同时进入租户控制面和运营平台，但运营平台只接收完成运维所需的聚合数据。

## 9. 可靠性验收

1. 随机终止 Runner 后，任务在最大尝试次数内完成或明确失败。
2. 同一任务并发完成请求只产生一个完成事件和一组账本条目。
3. 旧租约 worker 不能写入成果或完成任务。
4. 重复投递同一消息只执行一次业务动作。
5. 控制面宕机期间不产生无法解释的本地状态。
6. Runner 换机后能从 RustFS 最近快照继续工作。
7. 工作区全部员工休眠后容器停止，本地目录可清理，Postgres 引用和 RustFS 快照保留。
8. 死信消息不阻塞同一员工后续消息。
9. 单租户突发任务不会饿死其他租户。
10. 所有模型调用都能关联到 task_id、employee_id、tenant_id 和 usage_event_id。
11. 主控进程崩溃后可从控制面恢复，不丢失组织计划和在途任务。
12. 主控继任期间不会出现两个 Active 主控同时编排。
13. 运营平台不可用时，控制面按最后有效配额运行，安全封禁事件仍优先传播。
14. 重复或乱序配额事件不会导致配额回退或重复扣减。
15. Runner drain 后不再领取新任务，在途任务按策略完成或迁移。
16. 员工唤醒后发现列表按最新授权重新计算，不复用过期 Tool 权限。
17. Tool 授权撤销后，新调用立即被拒绝，在途调用不产生越权副作用。
18. 写 Tool 使用 `tool_call_id` 幂等，Runner 重试不重复执行领域动作。
19. WorkflowRun 在创建后固定版本，新增版本不影响在途运行。
20. 工作流步骤只能分派给具备所需能力的员工，不能自动扩权。
21. Runner 崩溃后步骤任务可通过租约恢复，已提交 Artifact 不丢失。
22. 记忆写入后即使索引延迟，权威记录和审计仍可恢复。
23. 删除请求在索引清除完成前保持逻辑删除并停止召回。
24. 索引任务重复执行不产生重复向量或关系。
25. Embedding 重建失败时旧索引继续可用，直到新索引验证通过。
26. 绩效周期任务重复执行不会生成重复评估或动作。
27. KPI 证据未收集完整时不生成最终结论。
28. 申诉复核未完成时高影响动作保持暂停。
29. 主控默认 7 天周期可配置，事件触发评估可提前运行。
30. 评估任务崩溃后可从证据和租约恢复，不丢失原始 KPI。
31. Runner 启动时获取当前 Tool Profile，不复用旧画像。
32. Auxiliary 展开后仍需执行层鉴权。
33. 画像切换不会导致员工获得超出 Authorized Tools 的权限。
34. Tool 激活事件丢失时，执行层仍拒绝未激活调用。
35. Restricted 审批完成后才能执行，审批撤销立即拒绝新调用。
36. 并发认领同一任务只有一个成功认领者。
