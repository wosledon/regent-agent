# 25 安全事件响应

- 版本：v0.1（待评审）
- 范围：SEV1～SEV4、Incident Commander、遏制、取证、通知、恢复和复盘
- 对应需求：FR-067、BR-081、BR-082、BR-083
- 对应缺口：G-38

## 1. 目标与边界

- 先控制影响，再保存证据和追责。
- 事件响应不等待员工逐级汇报。
- 主控不能压下事件或自行宣布恢复。
- 预授权自动遏制不得等待审批，破坏性动作仍需审批。
- 复盘默认无责归因员工个人，故意滥用另行处理。

## 2. 事件类型

- 跨租户访问或数据泄漏。
- 密钥、Token、证书泄漏。
- 恶意 Tool、MCP、Skill 或镜像。
- 数据外传、SSRF、容器逃逸。
- 审计篡改或证据缺失。
- 内容红线、侵权或欺诈发布。
- 内部滥用和越权。
- 大规模模型或工具滥用。

普通 Provider 故障归可靠性事件；伴随安全风险时关联安全事件。

## 3. 严重等级

| 等级 | 示例 | 响应 |
|---|---|---|
| SEV1 | 正在发生的跨租户泄漏、密钥失控、审计篡改 | 立即遏制，通知 Boss 和受影响租户 |
| SEV2 | 已遏制的入侵、恶意制品、越权发布 | 快速响应并升级负责人 |
| SEV3 | 被阻止的攻击、局部策略违规 | 调查和修复 |
| SEV4 | 可疑信号、未成功尝试 | 记录、观察和趋势分析 |

SEV1/2 必须进入 L3 或相应升级队列，不能只在私聊处理。

## 4. 角色

| 角色 | 职责 |
|---|---|
| Incident Commander | 范围、优先级、资源、恢复批准 |
| Technical Lead | 定位、修复、验证 |
| Evidence Lead | 取证、证据链、保管 |
| Communications Lead | 内部、租户和状态页通知 |
| Scribe | 时间线和决策记录 |

角色来自 `incident.command`、`security.respond` 等能力，不绑定固定岗位名。

## 5. 状态机

```text
Detected
  → Declared
  → Triaged
  → Contained
  → Eradicated
  → Recovering
  → Monitoring
  → Closed
```

- 可从任意安全阶段重新打开。
- 每次转换记录操作者、时间、理由和证据。
- IC 负责批准恢复和关闭。

## 6. 自动与人工边界

### 可立即自动执行

- 撤销可疑会话和 Token。
- 冻结受影响 Runner、Tool Profile 或制品版本。
- 阻断恶意域名和出站流量。
- 隔离容器。
- 暂停相关任务或模型调用。
- 创建事件和通知。

### 需要审批

- 删除数据。
- 关闭整个租户。
- 对外发布事件声明。
- 联系监管或执法。
- 支付赎金或对外承诺。
- 不可逆的大规模回滚。

不能为了等待审批放任 SEV1 扩散。

## 7. ContainmentAction

```text
action_id
incident_id
action_type
target_ref
reason
authorized_by
approval_ref?
executed_at
result
rollback_ref?
```

- 自动动作必须匹配预授权 Runbook。
- 人工动作绑定审批和参数。
- 所有动作幂等并审计。
- 失败动作进入重试或升级，不静默忽略。

## 8. 取证

证据包括：

- 审计链和验证报告。
- 日志、Trace 和指标快照。
- Postgres 和 RustFS 快照。
- 容器、镜像和制品 digest。
- 网络和工具调用记录。
- 受影响租户、员工、任务和凭据清单。

要求：

- 加密存储。
- SHA-256 和时间戳。
- 证据链保管记录。
- 访问和下载审计。
- 原始证据不覆盖。
- 高价值证据写入 WORM 存储。
- 普通事件聊天不粘贴秘密和完整 PII。

## 9. EvidenceItem

```text
evidence_id
incident_id
type
source_ref
content_hash
captured_at
captured_by
storage_ref
retention_policy
legal_hold
access_log_ref
```

- 证据与普通日志、记忆和遥测隔离。
- 只有事件角色可访问。
- 下载生成新的保管记录。
- 法律保留优先于普通删除。

## 10. 通知

- SEV1 立即通知 Boss、IC 和受影响租户负责人。
- SEV2 按影响范围升级。
- 状态页只发布脱敏影响。
- 外部通知包含已知事实、影响、措施和下次更新时间。
- 不猜测原因，不隐瞒已确认影响。
- 法律和监管通知按租户辖区策略执行。
- 通知失败重试，内部事件记录不丢失。

## 11. 恢复

恢复条件：

- 根因已控制。
- 恶意制品、账号或凭据已移除。
- 使用干净版本或可信备份。
- 密钥已轮换。
- 审计、账本和对象引用完成对账。
- 监控和回归测试通过。
- IC 批准；SEV1 还需租户/Boss 确认。

恢复后进入观察期，异常可重新打开事件。

## 12. 复盘

复盘包含：

- 时间线。
- 根因和促成因素。
- 控制有效性。
- 数据、租户和业务影响。
- 响应耗时。
- 改进行动、负责人和截止日期。
- Runbook、检测和测试更新。

- 默认无责归因员工个人。
- 故意滥用单独调查。
- 改进任务进入普通项目系统。
- 复盘和行动完成情况进入审计。

## 14. API 与 Tool

- `POST /incidents`：声明事件。
- `POST /incidents/{id}/assign`：指定 IC。
- `POST /incidents/{id}/actions`：执行遏制。
- `POST /incidents/{id}/evidence`：登记证据。
- `POST /incidents/{id}/notifications`：发送通知。
- `POST /incidents/{id}/recover`：申请恢复。
- `POST /incidents/{id}/close`：关闭事件。
- `POST /incidents/{id}/postmortem`：提交复盘。
- 普通员工只能报告和查看授权范围，不能修改证据或关闭事件。

## 15. 演练

- 跨租户泄漏桌面演练。
- 密钥泄露和轮换演练。
- 恶意 MCP/Skill 撤销演练。
- RustFS 或数据库证据恢复。
- 审计链篡改检测。
- 通知渠道失败。
- SEV1 自动隔离和人工恢复。
- 自托管无运营方场景。

## 16. 测试场景

1. SEV1 自动冻结受影响 Runner。
2. 自动撤销 Token 不需等待逐级审批。
3. 删除数据必须审批。
4. 主控不能关闭事件。
5. 证据 hash 和保管记录完整。
6. 普通日志不包含秘密和完整 PII。
7. 通知失败不丢失内部事件。
8. 恢复前验证审计和账本。
9. SEV1 恢复需要租户/Boss 确认。
10. 复盘行动进入项目系统。
11. 员工不会因无心之失自动受罚。
12. 自托管可在无运营方时完成响应。

## 17. 验收场景

1. SEV1～SEV4 可自动分级。
2. IC 和响应角色按能力分配。
3. 自动遏制无需等待逐级审批。
4. 破坏性动作具有审批和参数绑定。
5. 证据加密、哈希、WORM 并可追踪访问。
6. 通知只包含已知事实和脱敏影响。
7. 恢复需 IC 批准。
8. 主控不能压下或关闭事件。
9. 复盘行动可跟踪到完成。
10. 演练覆盖自托管和托管场景。
