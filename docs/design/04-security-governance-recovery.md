# 04 安全、治理与恢复

- 版本：v0.1（待评审）
- 范围：威胁模型、工具与容器安全、密钥、升级审批、审计、通知和备份
- 对应缺口：G-10、G-11、G-12、G-16、G-24

## 1. 安全目标与资产

安全目标是保证租户隔离、最小权限、密钥保密、动作可审计、故障可恢复。

| 资产 | 主要威胁 | 主要控制 |
|---|---|---|
| 模型密钥 | 泄漏、跨租户使用、日志泄露 | Postgres keyvault 信封加密、独立 Gateway 角色、key_ref、脱敏、轮换 |
| 租户数据与源码 | 跨租户读取、越权工具、备份泄漏 | tenant_id 强制过滤、RLS/约束、加密备份 |
| 宿主与 Docker | 容器逃逸、危险挂载、资源耗尽 | 容器基线、网络隔离、资源上限 |
| 审批权限 | 重放、参数篡改、自我批准 | action_hash、有效期、角色分离 |
| 账本与审计 | 篡改、删除、重复记账 | 只增不改、去重、哈希链、签名 Merkle 检查点、WORM 和外部锚定 |
| 服务可用性 | 提示注入、死循环、预算耗尽 | 工具策略、超时、预算硬限制 |

## 2. 信任边界

| 边界 | 边界两侧 | 必须校验 |
|---|---|---|
| 浏览器 → 控制面 | 用户输入 → 租户 API | 人类 JWT、tenant、role、CSRF/Origin |
| 运营浏览器 → 运营平台 | 提供方输入 → Ops API | Operator JWT、MFA、role、CSRF/Origin |
| 运营平台 → 控制面 | 系统管理 → 租户业务边界 | Ops service token、SupportGrant、范围、审计 |
| 控制面 → 网关 | 服务请求 → 密钥边界 | service token、aud、scope、预算预留 |
| Runner → 控制面 | 执行宿主 → 注册权威 | deployment token、assignment token、fencing |
| Runner → 沙箱 | 工具调用 → 不可信代码 | 能力策略、路径、网络、资源 |
| 沙箱 → Provider/互联网 | 生成内容 → 外部系统 | 域名白名单、重定向校验、内容降权 |
| 网关 → Provider | 代理 → 外部模型 | 租户密钥注入、超时、脱敏 |
| 备份 → 存储 | 运行系统 → 长期存储 | 加密、访问控制、完整性校验 |

运营方在托管模式下拥有基础设施访问权，但不能把“控制面不持钥”解释为“运营方无法访问网关”。运营平台必须通过独立身份、SupportGrant 和审计限制租户访问，不能直接读写租户业务库。代码开源、审计和自托管退出通道用于降低该信任风险。

## 3. 威胁模型与对策

| 威胁 | 场景 | 对策 |
|---|---|---|
| 跨租户访问 | 修改 tenant_id、复用 token、共享 Runner 串租户 | JWT 与资源交叉校验、仓储强制过滤、数据库约束、隔离测试 |
| 提示注入 | 网页、Issue、报告诱导员工或管家越权 | UntrustedContent、TaskGrant、执行层独立鉴权、审批门禁和审计 |
| 工具滥用 | 文件越界、SSRF、访问云元数据 | 路径规范化、网络白名单、元数据地址封禁、最小 capabilities |
| 容器逃逸 | privileged、docker.sock、危险 volume | 明确禁止、cap drop、seccomp、只挂授权卷 |
| 供应链攻击 | 恶意镜像、MCP、Skill、依赖或脚本 | 不可变 digest、签名、SBOM、准入审核、隔离试运行和按版本撤销 |
| 审批重放 | 旧批准用于新参数或新目标 | action_hash、资源版本、有效期、一次性执行 |
| 成本 DoS | Agent 循环调用模型或工具 | 任务预算、速率限制、最大步数、异常熔断 |
| 内部人员滥用 | 运营方读取数据或密钥 | 管理操作审计、双人审批、加密备份、自托管选项 |
| 运营令牌越界 | Operator token 访问租户 API 或超范围 SupportGrant | 独立 audience、强制 grant 校验、短时有效、自动撤销 |
| 同步投毒 | 伪造或乱序租户配额/封禁事件 | 服务身份、事件签名、版本号、幂等和乱序拒绝 |
| 日志泄漏 | Authorization 头、PII 或密钥进入 trace | 全边界 DLP、秘密隔离、PII 令牌化、审计元数据和密钥扫描 |
| 评测集泄漏 | 密封案例进入 Prompt、记忆或跨租户共享 | 隔离存储、最小权限、内容 hash、canary 和审计 |
| 记忆投毒 | 错误或恶意 claim 被摘要、组织化并影响决策 | claim 级检测/隔离、独立 CorrectionTask、影响图和版本化纠错 |
| 对象存储越权 | 枚举其他租户对象、覆盖证据或绕过签名 URL | 独立 IAM、短期凭据、租户前缀校验、版本控制和审计 |
| RLS 绕过 | 应用角色拥有 Owner 或复用错误租户上下文 | 非 Owner 运行角色、禁用 BYPASSRLS、SET LOCAL 和集成测试 |
| 内容违规 | 违法、侵权、冒充或欺诈内容进入生成和发布 | 版本化政策、可插拔检测、分级处置、复核和申诉 |
| 数据丢失 | Runner 磁盘损坏、备份不可恢复 | 外部工作区、成果存储、加密快照、恢复演练 |

## 4. 工具安全

### 4.1 策略模型

每次工具调用经过统一 Policy Enforcement Point：

```text
decision = allow | needs_activation | require_approval | deny
```

输入包括：租户、员工、岗位、任务、工具名、资源路径/URL、动作参数、数据敏感级别和当前审批状态。

默认拒绝未知工具、未知参数和未知资源。

Tool 权限分两层执行：

1. **授权层**：由身份、岗位、Capability 和 OrgManagementGrant 计算 Authorized Tools 权限上限。
2. **发现层**：`/tools/discover` 根据任务和 Tool Profile 返回 Primary 完整 Schema、Auxiliary 名称与简介。
3. **执行层**：每次 Tool Call 重新校验权限上限、当前激活状态、租户、资源范围、参数、编制/预算和审批要求。

执行结果分为 `Allowed`、`NeedsActivation`、`RequiresApproval`、`Forbidden`。未授权 Tool 不向 LLM 暴露 Schema；手动伪造调用只返回通用 `TOOL_NOT_AVAILABLE` 或 `FORBIDDEN`。写 Tool 必须幂等，调用者、参数哈希、策略结果和领域结果进入审计。

### 4.2 文件工具

- 只允许访问当前任务 worktree 和员工私有目录。
- 路径先解析符号链接，再验证是否位于授权根目录。
- 禁止绝对路径、`..`、主机路径、设备文件和 Docker 管理路径。
- 打开文件后使用文件描述符校验，避免检查后路径替换。
- 共享代码库可写范围由 worktree 限制；主分支写入必须通过合并流程。

### 4.3 HTTP 工具

- 只允许角色配置的 HTTPS 域名。
- DNS 解析后拒绝私网、回环、链路本地和云元数据地址。
- 每次重定向重新校验目标，禁止协议降级。
- 限制响应大小、超时、重试和内容类型。
- 抓取内容只作为数据嵌入，不能改变工具权限或系统指令。

### 4.4 Shell 与沙箱

- 不向员工提供宿主 shell。
- 唯一代码执行入口是 `sandbox.run`，强制使用一次性容器或授权团队工位。
- 命令、参数、镜像和环境变量在启动前校验。
- 沙箱不得接收模型密钥；如任务确需第三方密钥，使用短期、最小权限的独立凭据。

### 4.5 消息、记忆与审计工具

- 消息发送必须校验 sender、recipient、tenant 和 type。
- 记忆检索必须先按 tenant、个人 owner 和岗位范围过滤，再执行向量、关键词和图谱扩展；结果带来源、版本、置信度和有效期。
- 员工不能删除或改写审计事件。
- 管家只能使用只读工具清单，不能继承员工写工具。

### 4.6 工作流安全

- 工作流定义、提案和运行必须按租户隔离。
- 组织范围绑定岗位子树，只能沿作者岗位向上提名。
- 工作流不能授予 Capability、OrgManagementGrant 或 Tool 权限。
- 自动捕获必须脱敏，不保存密钥、原始系统提示词和未脱敏参数。
- 已采纳版本不可变，WorkflowRun 固定版本。
- 范围岗位关闭后停止新实例，不自动扩大可见范围。

### 4.7 记忆安全与遗忘

- 个人记忆默认私有，主控和其他员工不能直接检索。
- 组织记忆和知识库必须经过提名、审查和版本发布。
- 检索结果标记为数据，不能改变 Tool 权限或系统指令。
- 自动捕获不保存密钥、Authorization 头、原始系统提示词和未脱敏参数。
- 遗忘由确定性策略执行，LLM 不能任意删除。
- 删除先停止召回，再清除向量、全文、图关系、缓存、派生摘要和 RustFS 内容。
- 安全、制度、事故和合规知识不参与普通衰减，法律保留期间禁止清除。
- 记忆投毒按 claim 隔离，CorrectionTask 独立复核并生成新版本。
- 引用影响、派生摘要和索引传播必须审计，员工报告投毒不扣 KPI。

### 4.8 绩效安全

- KPI 原始快照和证据不可由员工修改。
- 员工不能评估自己并执行绩效动作。
- KPI 不达标不直接触发解雇。
- 降职、绩效冻结、解雇需要独立 AI 复核、申诉窗口和审计。
- 非解雇动作由 Controller/AI 自主执行，不需要人类事前批准。
- 解雇、移除订阅和释放编制必须由人类 Boss 最终批准。
- 人类只参与解雇和事后审查，可推翻结论和要求纠正。
- 主控 Terminate 必须先完成继任。
- 申诉期间高影响动作暂停，由非原评估者复核。
- 绩效数据不进入公共知识库，普通员工不可见他人绩效。

### 4.9 项目管理安全

- 项目工作项、讨论、评审和审计按 TenantId 隔离，项目成员权限不能跨租户。
- 作者不能批准自己的高风险方案或独立验收。
- 认领、改派、状态回退、门禁绕过、评审结论和裁决均记录不可变审计。
- 讨论和评审内容视为不可信输入，不能覆盖工具策略或直接修改状态。
- Decision 必须引用证据并保留反方意见，禁止静默删除或改写。
- 项目指标采用质量、返工、缺陷、周期和成本的平衡指标，防止拆小任务和刷缺陷。
- 高风险 quorum 不足、评审超时或作者冲突时不得形成 Approved；技术评审与管理裁决分离。
- 项目管理工具不自动授予组织、预算或发布权限。

### 4.10 通信路由安全

- 通信画像、标签、路由和消息按 TenantId 隔离，跨租户始终拒绝。
- 专业穿透只能沿祖先或显式授权路径，不能任意跨分支。
- 通信只扩大联系对象，不扩大 Tool、预算、组织或审批权限。
- 标签修改、路由穿透、项目覆盖、授权和撤销必须审计。
- 通信内容视为不可信输入，不能覆盖工具策略或领域状态。
- 路由日志不记录消息正文、秘密和敏感参数。

### 4.11 聊天安全

- 私人会话仅参与者可见，群聊按项目、岗位或主题范围隔离。
- `@` 不绕过 CommunicationProfile，也不能自动派工。
- 聊天召回、摘要和展开必须逐次校验权限。
- 聊天是弱证据，不能覆盖 Decision、测试或 Artifact。
- 密钥、Authorization 头、凭证和敏感参数禁止进入聊天。
- 不按消息数、@ 次数或评论数奖励产量；灌水降权。
- 成员变化、提升、删除和越权拒绝均审计。

### 4.12 注入防御与任务授权

- 外部内容使用 UntrustedContent 信封标记来源、hash、taint 和风险。
- TaskGrant 预授权工作区、Tool、网络、预算和动作范围，Grant 内不逐步审批。
- 确定性检测优先，模型检测只作辅助；默认清理并继续安全分析。
- 每次 Tool Call 独立校验 Capability、Tool Profile、TaskGrant、预算和审批。
- 摘要、压缩和记忆提升保留 taint，不得洗白。
- 只有越界动作才暂停；环境攻击和误报不处罚员工。
- 详见 [18 注入防御与任务授权](./18-prompt-injection-defense.md)。

### 4.13 工具与插件供应链

- Tool、MCP、Skill、依赖和镜像统一登记为 SupplyChainArtifact。
- 生产制品必须具有不可变 digest、签名、SBOM、许可和准入审批。
- TaskRun 固定制品版本，MCP 新增 Tool 默认禁用。
- 已批准制品免逐次审批，安装、升级和扩权才审核。
- 撤销按 digest 传播并分析影响，不删除证据或处罚员工。
- 详见 [20 工具与插件供应链](./20-tool-and-plugin-supply-chain.md)。

### 4.14 PII 与秘密脱敏

- 秘密只存在于密钥系统，业务系统只保存 secret_ref。
- PII 默认遮蔽、令牌化、假名化或匿名化。
- DLP 覆盖输入、Tool、模型出站、记忆、Artifact、日志、Trace、导出和通知。
- 审计只保存规则、类型、对象、动作和哈希。
- 删除传播到数据库、对象、索引、缓存、遥测副本和令牌映射。
- 误报不阻断安全任务，例外必须限期并审计。
- 详见 [21 PII 与秘密脱敏](./21-pii-and-secret-redaction.md)。

### 4.15 审计完整性

- 审计支持 standard、worm、anchored Profile，默认 standard。
- 审计事件追加写并维护连续 seq 和 event_hash 链。
- 每日签名 Merkle 检查点写入版本化 RustFS，worm Profile 启用对象保留。
- anchored Profile 只向外部锚点发布 root 元数据。
- 验证失败进入安全事件，不静默修复。
- 审计和锚点不包含秘密或完整 PII。
- 详见 [22 审计完整性](./22-audit-integrity.md)。

### 4.16 内容安全

- 内容安全覆盖输入、生成、聊天、Tool、代码、多媒体、记忆和对外发布。
- 使用版本化政策和可插拔检测器，正常内容放行，模糊复核，红线阻止。
- 分类器不是唯一法律判断，处置只限制违规动作。
- 误报可申诉，员工不因报告风险或误报受处罚。
- 对外发布必须通过内容门禁，法律取证单独加密并限权。
- 详见 [24 内容安全](./24-content-safety.md)。

### 4.17 安全事件响应

- 事件按 SEV1～SEV4 分级，由 Incident Commander 按能力负责。
- 预授权自动遏制可撤销凭据、冻结 Runner/Tool/制品、隔离容器和暂停任务。
- 删除数据、关闭租户、对外声明和联系监管必须审批。
- 证据加密、哈希、WORM 并审计，通知只发布已知事实和脱敏影响。
- 恢复需 IC 批准，复盘默认无责归因员工个人。
- 详见 [25 安全事件响应](./25-security-incident-response.md)。

### 4.18 账户身份与找回

- 账号密码注册登录属于第一梯队，密码使用 Argon2id 并统一限流。
- GitHub 登录使用 Authorization Code + PKCE、state 和精确 redirect URI。
- 外部身份以不可变 GitHub user id 绑定，不使用 login 作为主键。
- GitHub 已验证邮箱可唯一匹配并自动合并；本地未验证邮箱不得合并。
- 显式绑定和解绑必须由已认证账户发起，解绑前保留其他登录方式。
- 恢复码只存不可逆哈希、单次使用，重新生成使旧码失效。
- 找回成功后撤销旧会话和 Refresh Token。
- 本地邮件验证、备用邮箱、短信、问题、其他社交登录和完整人工找回暂缓。
- 详见 [26 账户身份与找回](./26-account-identity-and-recovery.md)。

### 4.19 企业 OIDC

- OIDC 属于第一梯队，使用 Authorization Code + PKCE、state、nonce 和完整 ID Token 校验。
- 身份键为 issuer+sub，新用户必须先邀请或预置，禁止默认 JIT 和邮箱自动建户。
- 组映射到显式能力，不自动授予 Owner。
- SSO 用户按 IdP 的 acr/amr 委托 MFA，运营 MFA 保持强制。
- required 模式必须配置独立紧急恢复，IdP 故障 fail closed。
- BFF、设备管理和本地 WebAuthn/TOTP 后置，基础 Cookie/CSRF 和撤销不削弱。
- 详见 [27 企业 OIDC 与认证策略](./27-enterprise-oidc-and-authentication-policy.md)。

### 4.20 多租户成员与所有权

- 账户可以加入多个租户，但每次会话只有一个 Active Tenant。
- 服务端必须校验成员关系和 membership_version，不信任请求体 Tenant ID。
- 每个租户唯一 Primary Owner，最后 Active 所有者不可移除。
- 代理权限限时、限范围、不可转授权，且不能执行主所有者专属操作。
- 切换租户重新签发会话并清空旧上下文。
- 跨租户不共享业务数据，成员移除只影响目标租户。
- 详见 [28 账户、租户与所有权](./28-account-tenancy-and-ownership.md)。

## 5. 容器安全基线

所有员工容器默认满足：

- 非 root 用户；`no-new-privileges`。
- 不挂载 `docker.sock`，不使用 `--privileged`。
- 移除非必要 Linux capabilities，使用 seccomp/AppArmor。
- 根文件系统只读，临时目录使用限额 tmpfs。
- 设置 CPU、内存、PID、磁盘和执行时间上限。
- 默认无网络；按角色只开放必要出口。
- 不使用宿主路径挂载；只挂载命名工作区卷。
- 镜像使用可信仓库和摘要锁定，启动前扫描。
- 不同租户使用不同网络和卷，不共享 Docker 控制面权限。
- 当前不挂载 GPU，也不提供本地推理容器。

团队工位与一次性容器使用同一基线；一次性容器额外启用 `--rm` 和更严格网络策略。

## 6. 密钥管理

- 网关使用信封加密：Provider API Key 由数据密钥加密，数据密钥再由主密钥包装。
- 密钥密文、包装数据密钥和版本元数据存储在 Postgres `keyvault` schema。
- Gateway 使用独立数据库角色访问 `keyvault`，ControlPlane、Runner、Operations 和前端角色无权访问。
- 主密钥来自环境变量、宿主机 secret 文件或外部密钥系统，不进入 Postgres。
- 控制面只保存 `key_ref`，不保存密钥字节或可逆密文。
- 日志、trace、错误响应和审计载荷必须脱敏。
- 密钥轮换、删除和访问都写入审计。
- 备份只包含 `keyvault` 中的密文和包装数据密钥，不包含明文主密钥。
- 主密钥备份与密钥库备份分离保管，恢复需要两份材料。
- 自托管模式下主密钥由用户控制；托管模式下运营方负有额外保管责任。

## 7. 升级与治理

### 7.1 动作分级

| 级别 | 示例 | 默认策略 |
|---|---|---|
| A 只读 | 查询组织、账本、记忆 | 允许并审计 |
| B 内部写 | 创建岗位、修改工作区 | 角色权限内允许 |
| C 外部写 | 发布产品、调用外部 API | 升级审批 |
| D 财务/高风险 | 超预算、购买服务、删除生产数据 | 升级审批 + 二次确认 |
| E 红线 | 侵权、违法、冒充人类、绕过审批 | 禁止并告警 |

### 7.2 升级事项

```text
Escalation:
  id, tenant_id, requested_by, employee_id, task_id
  action_type, action_hash, action_payload_ref
  impact, options, butler_recommendation, reason
  state, created_at, expires_at
  decided_by, decided_at, decision_reason
  execution_id, execution_result
```

- `action_hash` 覆盖动作类型、目标、参数、资源版本和租户。
- 审批有效期内参数变化会使事项失效。
- 同一审批只能执行一次；执行服务重新校验状态、哈希和权限。
- 发起者不能批准自己的高风险动作；股东批准也不能绕过红线禁止策略。
- 超时默认拒绝，不自动视为同意。
- 审批按 T0～T3 和禁止分级，高风险动作可要求双人 quorum。
- 人类缺席时优先由 Controller 与直接下一层协商；只有共识、授权和预算充足且不触红线时才自主执行。
- 不能处理时才使用 ApprovalDelegation、备用审批人或 Co-Owner 路由。
- 委托必须限时、限范围、双方确认且不可转授权，不能覆盖所有者专属事项或自我批准限制。
- 完整路由、SLA 和审计见 [36 审批委托与缺席](./36-approval-delegation-and-absence.md)。

### 7.3 人类指令

股东通过管家形成的指令必须经过显式确认，控制面创建带审计的 `human_directive` 事件。管家只负责起草，不能直接调用写工具。

### 7.4 运营支持访问

- 运营人员访问租户数据必须持有有效 SupportGrant。
- Grant 绑定 operator、tenant、scope、权限和有效期，默认只读。
- 写操作需要更高权限和租户明确批准；紧急访问需要双人审批。
- 任何 grant 都不能读取模型密钥或绕过红线策略。
- 访问、拒绝、撤销和到期均写入运营审计，租户可查看。
- 运营平台不能通过直接数据库访问绕过 grant 校验。

## 8. 审计与可观测性

### 8.1 审计事件

至少记录：

- 认证、权限和租户变更。
- 岗位、员工、任务和项目状态变化。
- 工具调用、外部动作和审批执行。
- 模型配置、密钥引用和预算变更。
- 用量、账本更正、备份和恢复。
- 运营登录、角色变更、SupportGrant、租户暂停、配额调整、drain 和紧急访问。

审计事件只增不改。应用账号没有 UPDATE/DELETE 权限；每日生成哈希清单并写入独立存储。

### 8.2 追踪

`correlation_id` 贯穿人类请求、任务、消息、模型调用和工具执行。`request_id` 用于单次 HTTP 诊断。日志不得包含密钥、完整 Authorization 头或未脱敏请求体。

## 9. 哨兵与通知

Sentinel 是纯程序算法，不调用 LLM、不是 Agent、不占编制。它只监控指标、应用阈值和规则、生成事件，并执行预定义安全动作；开放式经营决策仍交给主控或 Boss。

| 级别 | 触发示例 | 动作 |
|---|---|---|
| L0 | 普通指标波动 | 日志和指标 |
| L1 | 单次任务失败、轻微延迟 | 日报汇总 |
| L2 | Runner 孤儿、预算预警、毒消息 | 告警并唤醒主控或授权负责人 |
| L3 | 跨租户风险、硬预算超支、密钥异常、服务不可用 | 站内通知股东、自动冻结相关动作、生成升级 |

第一梯队只在仪表盘通知中心投递，不实现 Telegram、邮件、其他 IM 或 Webhook。通知先持久化，再通过 SignalR 实时提示；失败可重试和重新拉取。L3/SEV1 不受普通静默时段限制，详见 [41 内部通知中心](./41-internal-notification-center.md)。

## 10. 备份与恢复

### 10.1 备份内容

- 控制面数据库：租户、组织、任务、消息、账本、审计、Outbox。
- 运营平台数据库：租户账户、套餐、配额、订阅、资源池、事件、SupportGrant 和运营审计。
- RustFS：Git Bundle、工作区快照、报告、测试和发布包。
- Postgres：工作区元数据、Git 引用和对象元数据。
- ReleaseManifest、基础镜像 digest、本地镜像 ID、schema/config 版本和迁移清单。
- Postgres `keyvault` schema：由 Gateway 备份密文和包装数据密钥，不由控制面解密。
- 配置与部署清单：镜像摘要、环境变量名称、迁移版本，不包含明文秘密。

### 10.2 可选 Profile 与恢复目标

- 备份默认关闭，实施后置，不作为 MVP 优先项。
- Postgres 全量、PITR、RustFS、密钥库、异地和演练独立开关。
- 未启用组件不承诺 RPO/RTO，不计入备份成功率。

| 组件 | 启用后目标 RPO | 启用后目标 RTO |
|---|---:|---:|
| Postgres 全量 | 24 小时 | 8 小时 |
| 账本与审计 PITR | 15 分钟 | 4 小时 |
| RustFS | 24 小时 | 8 小时 |
| 密钥库 | 15 分钟 | 2 小时 |

有效 RPO/RTO 必须来自最近成功备份和实际演练，配置目标不等于已实现能力。详见 [31 可选备份与恢复](./31-backup-profiles-and-recovery.md)。

### 10.3 恢复流程

运营平台负责制定策略、发起作业、记录审批和输出报告；各组件只通过自己的备份 API 导出数据，不共享数据库恢复权限。未配置备份时拒绝恢复并返回 not_configured。

1. 校验 BackupProfile 和可用恢复点。
2. 冻结写入并记录恢复点。
3. 恢复 Postgres 和 RustFS 到一致快照点，并核对对象引用。
4. 恢复 Postgres `keyvault` schema 密文；主密钥从独立保管处注入。
5. 校验 ReleaseManifest、schema 版本、租户数量、账本哈希、工作区引用和密钥版本。
6. 启动网关并执行每个租户的最小测试调用。
7. 启动控制面、Runner 和调度器，重放未完成 Outbox 和 tombstone。
8. 对账任务、账本和审批状态，恢复写入。
9. 输出恢复报告和暴露窗口。

### 10.4 演练

- 恢复演练默认关闭，可按周、月、季度配置。
- 启用后每月可执行单租户恢复，每季度可执行全量和密钥恢复。
- 演练必须验证数据完整性，而不只是服务进程启动。
- 关闭演练不产生虚假成功率。

## 11. 安全验收

1. A 租户无法通过路径、JWT、消息、存储或容器访问 B 租户资源。
2. 所有容器拒绝 privileged、docker.sock 和宿主路径挂载。
3. 文件工具无法通过符号链接或绝对路径越界。
4. HTTP 工具无法访问私网、回环和云元数据地址。
5. 外部内容不能改变工具权限或触发未审批动作。
6. 已批准事项在参数变化后不能执行。
7. 日志和 trace 不包含模型密钥或完整认证头。
8. 备份恢复后账本、工作区和密钥引用一致。
9. 管理账号无法修改或删除审计事件。
10. 跨租户、硬预算超支和密钥异常均生成 L3 事件与升级记录。
11. 租户删除请求在保留期结束后清除业务数据、工作区和密钥引用。
12. 归档清单包含数量、哈希和版本信息，可在隔离环境校验。
13. 关键 SLO 有指标、告警和错误预算策略。
14. 日志脱敏测试覆盖请求头、错误响应和 trace 属性。
15. Operator token 不能访问租户 API，租户 token 不能访问 Ops API。
16. SupportGrant 超时、超范围或撤销后访问立即拒绝。
17. 运营平台不能通过直接数据库访问绕过支持授权。
18. 暂停租户和 drain Runner 等运维动作均有审批和审计。
19. 运营数据库与租户业务库可以分别恢复，并保持配额和状态一致。
20. Sentinel 规则不能调用模型、创建岗位、批准升级或修改开放式经营决策。
21. 普通开发无法通过 Tool 发现接口获得组织管理 ToolManifest。
22. 未授权 Tool 调用在执行层被拒绝，且不泄露工具 Schema。
23. Tool 授权撤销后，发现和执行同时失效。
24. 写 Tool 的重复调用不产生重复领域副作用。
25. 工作流不能跨租户读取定义、运行或证据。
26. 工作流不能提升执行者权限或调用未授权 Tool。
27. 自动捕获内容不包含密钥、原始系统提示词和未脱敏参数。
28. 范围岗位关闭后工作流停止新实例，不自动扩大范围。
29. 个人记忆不能被主控或其他员工检索。
30. 记忆检索的每一跳都重新校验租户和范围。
31. 过期记忆停止普通召回，历史仍可授权追溯。
32. 删除后向量、全文、图关系、缓存和派生摘要均停止召回。
33. LLM 不能任意删除记忆或绕过确定性遗忘策略。
34. 自动捕获不包含密钥、原始系统提示词和未脱敏参数。
35. 员工不能修改 KPI 原始快照或评估自己。
36. KPI 不达标不会直接触发解雇。
37. 高影响绩效动作在复核和申诉窗口完成前暂停。
38. 主控无继任者时不能被解雇。
39. 非原评估者可以维持、修改或撤销绩效动作。
40. 员工绩效数据不进入公共知识库或对普通员工公开。
41. Tool Profile 不能扩大 Authorized Tools。
42. Auxiliary Tool 展开后仍需执行层鉴权。
43. Restricted Tool 未审批时不能执行。
44. 普通开发不能通过激活获得组织管理和预算工具。
45. 高级岗位的能力继承必须显式声明，不按组织层级自动扩散。
46. Tool 展开、激活、审批、拒绝和调用均有审计。
47. 项目工作项和讨论不能跨租户访问。
48. 高风险评审作者与评审者必须分离。
49. 讨论内容不能直接修改工作项状态。
50. Decision 不可删除且保留反方证据。
51. 门禁绕过、状态回退和改派必须审计。
52. 项目管理工具不能修改组织或预算。
53. 拆小任务、刷缺陷或刷评论不能单独提高绩效结论。
54. 跨租户通信路由始终拒绝。
55. 专业穿透不能绕过作者评审或发布审批。
56. 普通员工不能自行添加标签或扩大联系人范围。
57. 项目覆盖过期后不能继续越级通信。
58. 通信内容不能改变工具策略或领域状态。
59. 路由日志不包含消息正文和秘密。
60. 路由穿透、授权和撤销均可审计。
61. 私人聊天不能被非参与者搜索或召回。
62. 群聊摘要不能泄露不可见线程。
63. `@` 不能绕过通信权限或自动派工。
64. 聊天内容不能改变工具策略或领域状态。
65. 密钥或凭证聊天被拒绝并告警。
66. 聊天提升、成员变化和越权拒绝均可审计。
67. 高风险 quorum 不足时不能批准。
68. 评审超时不会自动通过。
69. 作者不能批准自己的高风险工作。
70. 技术评审与管理裁决必须分离。
71. Decision 必须保留反方和证据。
72. 红线和租户隔离不能被裁决推翻。
73. 非解雇绩效动作不需要人类事前批准。
74. 解雇、移除订阅和释放编制必须由人类 Boss 最终批准。
75. 人类只参与解雇和事后审查，不参与其他日常绩效动作。
76. 人类事后审查可以推翻结论和要求纠正，但不得删除历史证据。

## 12. 数据保留、删除与导出

### 12.1 保留类别

| 数据 | 默认策略 |
|---|---|
| 公司消息 | 在线 90 天，归档 1 年 |
| 账本与审计 | 租户终止后保留 7 年，法律保留优先 |
| 任务记录 | 在线 180 天，归档 3 年 |
| 项目成果 | 项目存续期，终止后归档 1 年再审核 |
| 日志 / 指标 / Trace | 14 天 / 30 天 / 7 天 |
| 个人/组织记忆 | 按保留类衰减、停止召回、归档或清除 |
| 知识库 | 已发布版本长期保留，替代版本可追溯 |
| 密钥 | 模型删除或租户终止后立即撤销，不保留可用凭据 |
| 备份 | 默认最长 35 天，软删除 tombstone 在恢复时重放 |

完整保留表和归档规则见 [30 在线保留与归档](./30-retention-and-archiving.md)。

法律保留或安全事件可暂停物理清除，但必须记录原因、范围、审批人和到期时间，且不得恢复用户访问。

### 12.2 账户与租户软删除

1. 账户本人或 Primary Owner 提交请求并完成最近认证。
2. 立即软删除，停止登录、任务、召回、搜索和普通访问。
3. 账户恢复窗口 30 天，租户 7 天。
4. 账户注销前必须处理唯一 Primary 所有权。
5. 窗口内可重新认证恢复；清除开始后禁止恢复。
6. 窗口结束后物理清除并生成 DeletionProof。
7. 备份到期清除，恢复备份必须重放 tombstone。
8. 法律保留只阻止物理清除，不恢复访问。

详见 [29 账户与租户软删除](./29-account-and-tenant-soft-deletion.md)。

### 12.3 数据导出与迁移

- Owner 自助数据导出与校验迁移包已提供；跨环境导入、密钥迁移和托管退出流程仍后置。
- 不确认 Export Bundle、ZIP64、JSONL、导入 CLI 或密钥迁移方案。
- 未来重启时必须单独评审格式、完整性、所有者映射、密钥边界和退出顺序。
- 开源、自托管部署、归档、审计和软删除不受影响。

导入工具必须校验 manifest、哈希和 schema 版本；不兼容时拒绝导入并给出迁移建议。

## 13. 可观测性与服务目标

### 13.1 Elastic 可观测性后端

- 四个服务和两个前端统一 OpenTelemetry SDK。
