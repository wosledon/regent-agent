# 23 离职、调岗与再入职

- 版本：v0.1（待评审）
- 范围：唯一工号、任职周期、调岗、再入职、待驱逐、Boss 决策、交接和私有数据
- 对应需求：FR-065、BR-074、BR-075、BR-076、BR-077
- 对应缺口：G-36

## 1. 目标与边界

- 员工工号是永久身份，不随岗位或任职周期变化。
- 调岗不是离职，再入职不是简单恢复旧会话。
- 低统一评级只进入待驱逐队列，不直接解雇。
- 非解雇绩效动作由 Controller/AI 自主执行，不需要人类事前批准。
- 主控只能否决候选；录用、再入职和移除订阅由 Boss 最终批准。
- 人类只参与解雇和事后审查，可推翻结论和要求纠正。
- 公司成果保留，私有数据隔离，秘密吊销或轮换。

## 2. 身份模型

```text
Employee
  employee_id
  employee_no
  status
  created_at

EmploymentPeriod
  id
  employee_id
  started_at
  ended_at
  status
  reason

PositionAssignment
  id
  employee_id
  position_id
  started_at
  ended_at
```

- `employee_no` 全局唯一、不可变、永不复用。
- `employee_id` 是内部 UUID。
- 历史任务、工作台账、绩效和审计关联 `employee_no`。
- 同一员工不能同时有两个 primary assignment。

## 3. 调岗

```text
结束旧 PositionAssignment
  → 创建新 PositionAssignment
  → 重算 Capability、Tool Profile 和模型绑定
  → 保留 employee_no、运行时、个人记忆和历史绩效
```

- 调岗在同一数据库事务完成。
- 旧岗位权限立即撤销。
- 在途任务按安全点交接或继续。
- 调岗不创建新工号，不触发私有数据清除。
- 主控可在授权组织范围内执行调岗，Boss 可复核或否决。

## 4. 再入职

再入职复用原 `employee_no`，但创建新 EmploymentPeriod：

```text
Employee（保留）
  → EmploymentPeriod（新）
  → PositionAssignment（新）
  → 新会话、Token 和凭据
  → 新 TaskGrant
```

- 旧 Token、密钥和会话永不恢复。
- 私有记忆默认不自动恢复。
- 公司成果和历史绩效仍关联旧身份。
- 个人经验如需恢复，由员工重新提交并审查。
- 主控只能推荐，Boss 最终批准。

## 5. 招聘决策权限

| 事项 | 主控 | Boss |
|---|---|---|
| 候选人不符合要求 | 可决定不录用并记录证据 | 可复核 |
| 录用候选人 | 只能推荐 | 最终批准 |
| 再入职 | 只能推荐 | 最终批准 |
| 普通调岗 | 授权范围内自主执行 | 事后审查，不事前审批 |
| 惩罚性降职 | 独立 AI 复核后自主执行 | 事后审查，不事前审批 |
| 绩效冻结 | 独立 AI 复核后自主执行 | 事后审查，不事前审批 |
| 进入待驱逐列表 | 可提名 | 查看 |
| 移除订阅/离职 | 不能执行 | 最终决定 |
| 移除主控 | 不能执行 | 必须先完成继任 |

- Boss 缺席时录用和移除保持待定，超时不默认通过。
- 人类事后审查可推翻非解雇动作并要求纠正，但不构成日常事前审批。
- 主控不能通过停唤醒、不续签、零预算或拒绝分配变相移除员工。
- 所有决定绑定工号、岗位、评估版本和证据。

## 6. PendingRemovalQueue

统一评级持续很低时进入：

```text
Nominated
UnderReview
Appeal
BossDecision
Executed
Cancelled
```

入列条件：

- 统一评级低于版本化门槛。
- 连续多个评估周期。
- 样本足够。
- 已区分员工、模型、流程和管理原因。
- 完成独立复核。

入列不停止员工，不自动冻结，也不自动解雇。

## 7. 待驱逐证据包

- 工号、岗位和任职周期。
- 统一评级及趋势。
- 质量、可靠性、能力和成本证据。
- 改进计划和历史效果。
- 原因归因。
- 独立复核结论。
- 申诉状态。
- 移除后的交接影响。

Boss 可选择保留、辅导、调岗、继续观察或移除订阅。

## 8. 数据分类

### 公司所有，保留

- 岗位和任职历史。
- 任务、评审、决策、工作台账。
- 已提交代码和 Git 历史。
- 项目 Artifact、测试和发布记录。
- 组织记忆、知识库和已发布 Skill。
- 审计、账本和绩效归档。

### 项目共享，交接

- 项目聊天和主题讨论。
- 未完成任务、缺陷和评审请求。
- 交接记录和依赖。
- 项目级工作区快照。

### 员工私有，隔离

- 个人记忆。
- 私人聊天。
- 私人草稿、未发布 Skill 和个人工作流。
- 私有目录和未提交实验。

### 秘密，吊销或轮换

- API Key、Token、证书。
- 第三方凭据和私有仓库凭据。
- 个人设备或恢复码。

秘密不转移、不导出、不继承。

## 9. 离职流程

```text
Boss 批准并确定生效时间
  → 停止新认领和新会话
  → 在途任务到安全点
  → 生成工作区快照
  → 撤销会话、Token、Tool 和通信权限
  → 移除员工运行/模型订阅
  → 释放编制
  → 生成交接包
  → 数据分类和隔离
  → 保留期后清除私有数据
  → 输出离职证明
```

- 生效后立即拒绝新调用；现有 Cookie 会话和 Agent Assignment Token 不能继续访问。
- Pending/Assigned/InProgress/InReview/Blocked 任务转 `Interrupted`，清除租约所有者、token 和到期时间；审计记录中断任务 ID。
- 任务认领排除 terminated 员工，旧租约迟到提交返回冲突，不恢复员工权限。
- 在途工具调用按策略取消或完成；本地工作区在快照确认后清理。
- 所有步骤幂等并审计。

### 9.1 当前审批执行边界

- offboard、terminate、hire、rehire 只通过 `ApprovalExecutionService` 执行；旧的组织服务旁路不再公开。
- `ApprovalRecord` 保存稳定请求用户 ID、目标员工/候选人/岗位 ID、`DecidedBy`/`DecidedAt` 与 v2 `action_hash`。v2 哈希覆盖 `tenant_id`、规范化 `action_type` 和三个稳定目标 ID；v1 哈希只保持可读，永不执行，标题不参与目标推断。
- T2 决定与执行都要求当前 Owner/CoOwner 成员关系或动作精确匹配的 `approval.*` capability；Password 不授予额外权限，普通 `tenant.write` 不能批准解雇、离职、录用或再入职。
- 执行层重新计算 v2 哈希，并要求同租户、动作类型、全部目标 ID、Approved、未过期、未消费且存在授权决定身份完全匹配；关系库使用条件更新原子消费，InMemory 使用静态信号量回退。
- 服务层幂等键按 `approval-execution:{approvalId}:{actorId}` 隔离；同一 actor、key、hash 可重放，不同 hash 冲突，其他 actor 不共享缓存，消费后的新 key 返回 409。
- 审批消费、领域变更、审计、确定性 `approval.execution.committed` Outbox 和幂等结果在同一租户串行化事务提交；配额或状态失败回滚消费。员工状态转换使用 `State <> Terminated` 条件更新，主控移除要求同一 Controller 岗位已有其他 Active 员工的未结束 Primary 任职周期；主控身份按该任职周期的岗位判定，不按显示名判定。调岗和关闭主控岗位复用同一继任校验与事务边界；Controller 岗位自身禁止合并和同名副本，必须通过显式继任调岗。
- Outbox handler 加载审批并校验租户、动作、全部目标、决定/消费身份、消费时间、v2 哈希和确定性消息 ID 后才产生副作用；客户端不能发布或触发内部 Outbox。
- 私有记忆按稳定 `AuthorEmployeeId` 与 `AuthorEmploymentPeriodId` 隔离，不按显示名批量隔离；Agent 捕获和检索都携带当前任职周期，旧周期 claim 即使因 Outbox 延迟仍为 Active 也不能被新周期 Token 读取。隔离与向量删除在终止事务提交后由 `ApprovalExecutionOutboxHandler` 执行，覆盖 Active、Disputed、Quarantined 和 Candidate；提交前故障不会触碰 JSON claim 或向量索引。无周期 ID 的历史 claim 以被结束任职周期的 `EndedAt` 为上限，迟到 Outbox 只按旧周期 ID 或同一截止时间幂等补隔离，不得影响再入职后的新 claim。仅当租户内同名员工唯一且调用方显式请求时，才允许历史无稳定 ID 的 claim 走姓名兼容路径。再入职不会恢复已隔离 claim。
- 终止事件携带被结束的 `employment_period_id`。Agent Assignment Token 携带同一 `credential_epoch`，ControlPlane 与 Gateway 都校验当前未结束任职周期；再入职创建新周期，旧 Token 永不复用，迟到终止事件只断开旧周期连接。
- Outbox 按消息隔离失败并有界退避；达到上限进入 `Quarantined`，保留 Attempts、NextAttemptAt 和非敏感 LastError，不阻塞后续消息或其他租户。

## 10. OffboardingHandoff

包含：

- 未完成任务和当前状态。
- 已提交 commit、分支和 Artifact。
- 未提交改动快照。
- 评审、缺陷和决策引用。
- 外部依赖和下一步。
- 接收人和确认时间。

不包含：

- 个人记忆。
- 私人聊天。
- 秘密和可逆凭据。
- 与工作无关的私有实验。

- 直接 Leader 指定接收人。
- 未提交改动先做秘密和版权扫描。
- 接收人确认后任务回到 Ready 或 Blocked。
- 不允许静默丢弃未提交成果。

## 11. 私有数据保留

| 数据 | 默认处理 |
|---|---|
| 个人记忆 | 隔离，30 天后清除 |
| 私人聊天 | 停止访问，30 天后清除 |
| 个人草稿 | 隔离，不自动转组织资产 |
| 本地工作区 | 快照后尽快清理 |
| 公司成果 | 保留并重新指派所有权 |

- 法律保留期间禁止清除。
- 删除通过 Q-022 的传播机制执行。
- 输出 DeletionProof。
- Leader 默认不能读取私有记忆和私人聊天。

## 12. 紧急访问

- 安全、法务或合规需要时，通过独立授权获取指定范围。
- 记录理由、审批、范围和下载 hash。
- 不提供管理员任意浏览员工私有数据的通道。
- 紧急访问不改变数据所有权。

## 13. 审计与证明

记录：

- 批准人和生效时间。
- 解雇的人类批准记录及事后审查结果。
- 任务交接和接收人。
- 权限撤销时间。
- 快照、Artifact 和 hash。
- 私有数据隔离和清除范围。
- 秘密轮换。
- 法律保留项。
- 再入职关联策略。

输出 `OffboardingRecord` 和 `DeletionProof`。

## 15. 测试场景

1. 员工有在途任务时离职。
2. Runner 在离职后尝试提交。
3. 私有记忆被 Leader 检索。
4. 私人聊天被项目成员读取。
5. 未提交改动含密钥。
6. 公共 Skill 与个人草稿混淆。
7. 法律保留阻止删除。
8. 再入职请求恢复旧记忆被拒绝。
9. 主控尝试自行移除订阅被拒绝。
10. Boss 缺席时移除决定保持待定。
11. 调岗保留工号和历史。
12. 再入职复用工号但创建新凭据。
13. 待驱逐员工在申诉期间不被执行。
14. 主控无继任者时不能被移除。
15. 删除传播遗漏向量或缓存。
16. 降职或绩效冻结等待人类事前批准被拒绝。
17. 解雇缺少人类 Boss 批准时无法执行。
18. 人类事后审查可以撤销错误降职并要求恢复权限。

## 16. 验收场景

1. 工号全局唯一且永不复用。
2. 调岗保留工号和员工运行时。
3. 再入职创建新任职周期和凭据。
4. 主控只能否决候选，不能自行录用或移除订阅。
5. 待驱逐队列不自动执行处罚。
6. Boss 决定绑定证据和申诉状态。
7. 公司成果完成交接。
8. 私有记忆和聊天不被自动转移。
9. 秘密被吊销或轮换。
10. 离职证明和删除证明完整可审计。
