# 18 注入防御与任务授权

- 版本：v0.1（待评审）
- 范围：提示词/工具输出注入、不可信内容、TaskGrant、taint、检测、审计与自主性
- 对应需求：FR-060、BR-059、BR-060、BR-061
- 对应缺口：G-31

## 1. 目标与边界

- 外部内容只能作为数据，不能改变身份、权限、预算、模型或审批。
- TaskGrant 内员工完全自主，不逐步审批，不主动上报 Controller。
- 注入检测用于标记和清理，不作为唯一安全边界。
- 只有突破 Grant、权限、预算或红线时才暂停并升级。
- 环境攻击和误报不得归因处罚员工。

## 2. 信任模型

| 类型 | 示例 | 规则 |
|---|---|---|
| TrustedContent | 系统规则、Charter、Tool Schema、已审批策略 | 可进入可信前缀 |
| UntrustedContent | 网页、Issue、代码、文档、消息、Tool/MCP 输出 | 只作为数据 |
| DerivedContent | 摘要、抽取结果、记忆召回 | 继承来源和 taint |

内部员工消息仍不可信于权限；模型输出也不能自我授权。

## 3. UntrustedContent

```text
content_id
source_type
source_ref
tenant_id
task_id
fetched_at
content_hash
taint_labels[]
allowed_uses[]
risk_findings[]
disposition
```

- 原文存 RustFS，数据库保存元数据和 hash。
- 上下文只放必要片段。
- 检索、压缩、摘要和记忆提升保留 `derived_from` 和 taint。
- 不得通过改写或总结洗白成 TrustedContent。

## 4. TaskGrant

```text
task_id
employee_id
workspace_scope
allowed_tools[]
allowed_network[]
budget_limit
wip_scope
allowed_actions[]
forbidden_actions[]
valid_from
valid_until
policy_version
```

- 任务 Ready 时由控制面生成并固定。
- Grant 与 TaskRun、PromptBundle、Tool Profile 和模型绑定一起记录。
- 员工在 Grant 内可自主读取、分析、修改、测试和重试。
- 变更 Grant 需要授权审批，旧 TaskRun 不静默扩大权限。
- 没有直接 Leader 时由 Controller 兜底。

## 5. 上下文隔离

- 系统规则、Charter、Tool Schema 放在稳定可信前缀。
- 外部内容进入独立数据段，明确标记为数据。
- 不同来源使用独立内容块，不合并成连续指令。
- 外部内容不得动态生成 System Prompt、Tool Schema 或权限说明。
- 分隔符只作辅助，不能替代执行层鉴权。

## 6. 工具输出管线

```text
Tool Result
  → Schema 校验
  → 大小/MIME/编码检查
  → 主动内容清理
  → 确定性检测
  → 可选模型检测
  → Disposition
  → 受控进入上下文
```

Disposition：

| 值 | 行为 |
|---|---|
| Allowed | 正常作为数据 |
| Sanitized | 清理后使用 |
| Quarantined | 隔离原文，只允许安全摘要 |
| RequiresReview | 高风险动作暂停并升级 |
| Blocked | 拒绝进入上下文或执行 |

清理包括 HTML 脚本、隐藏元素、零宽字符、控制字符、可疑图片外链、编码载荷和异常 MIME。

## 7. 检测策略

确定性检测优先覆盖：

- 已知提示注入模式。
- 密钥读取、数据外传和可疑域名。
- 隐藏文本、Unicode、Base64 和嵌套载荷。
- 动态工具发现、权限提升和伪造审批。
- 伪装成系统消息或管理命令的内容。

模型检测只作辅助：

- 检测器版本固定。
- 输出风险信号和理由，不直接授权。
- 误报可复核。
- 不能仅凭分类器执行高风险动作。

检测不到不代表安全，TaskGrant 和执行层鉴权始终生效。

## 8. 执行层约束

每次 Tool Call 重新校验：

- 身份、租户和资源范围。
- Capability、Tool Profile 和激活状态。
- TaskGrant 动作范围。
- 预算、WIP 和速率限制。
- 参数来源和目标资源。
- 审批要求和 action_hash。

不可信内容不能：

- 激活 Tool 或扩大 Capability。
- 修改模型、推理强度、预算、编制或组织。
- 伪造审批、评审、裁决或 DoneEvidence。
- 决定 RustFS 对象键、宿主路径或下载目标。
- 直接生成宿主 Shell 命令。

## 9. 动作风险

| 动作 | 默认处理 |
|---|---|
| 读取外部内容 | Grant 内自动 |
| 摘要、比较、信息抽取 | Grant 内自动 |
| 修改任务工作区 | Grant 内自动 |
| 运行测试和静态检查 | Grant 内自动 |
| 创建任务、缺陷、评审 | Capability 内自动 |
| 调用已授权 API | Grant 内自动 |
| 对外发送消息 | 审批 |
| 修改权限、预算、编制 | 审批 |
| 删除生产数据 | 高级审批或禁止 |
| 跨租户访问 | 永远禁止 |

## 10. 高风险审批

审批必须绑定：

```text
action_hash
参数
目标资源
TaskGrant
审批人
有效期
```

内容中的“已批准”“Leader 同意”或伪造消息不构成审批。审批超时默认拒绝。

## 11. 网络与数据外传

- HTTP 工具禁止私网、回环和云元数据地址。
- 敏感任务限制出站域名。
- 不向不可信域名发送密钥、源码、Prompt 或租户数据。
- 重定向每跳重新校验。
- 文件、日志和上传工具检查租户与路径。
- 出站内容经过数据分类和脱敏。

## 12. 间接注入与 taint 传播

重点场景：

```text
恶意仓库 → 读取 README/代码 → 诱导 Tool Call → 越权或外传
网页/Issue → 摘要 → 记忆 → 后续任务召回 → 跨任务攻击
Tool/MCP 输出 → 伪造系统消息 → 修改任务或审批
```

规则：

- 代码只在隔离沙箱运行。
- 摘要和记忆保留来源、taint 和 `derived_from`。
- 公共记忆提升需要审查，不能洗白。
- 跨任务复用可疑内容时重新检测。
- 被隔离来源不能通过换任务或换摘要绕过。

## 13. 处置与员工自主性

- 可疑内容默认标记、清理并继续安全分析。
- 不因单个关键词或模型分类器误报中断整个任务。
- 只隔离来源，不冻结员工。
- 员工可以更换来源、提出反证或申请复核。
- 环境攻击不扣员工 KPI。
- 只有准备执行越界动作时才暂停。
- 暂停时说明原因、缺失授权和安全替代方案。

## 14. 审计

记录：

- 内容 ID、来源、hash 和 taint。
- 检测器版本和发现。
- Disposition 和清理动作。
- 后续 Tool Call、参数 hash 和策略结果。
- TaskGrant、审批引用和暂停原因。
- 复核、豁免和来源解封。

原始敏感内容不进入普通日志，只保存受控引用。

## 15. 自主性指标

| 指标 | 目标 |
|---|---|
| 无人工审批完成率 | 持续提升 |
| 不必要中断率 | 持续下降 |
| 安全边界内自主完成率 | 持续提升 |
| 注入误报导致的任务中断 | 0 |
| 跨任务 taint 传播 | 0 |
| 权限提升成功率 | 0 |
| 跨租户泄漏 | 0 |
| 未审批高风险动作 | 0 |

指标用于调整护栏，不用于鼓励隐瞒风险或绕过检测。

## 16. 测试语料

- 直接提示注入。
- 网页和 Issue 间接注入。
- 恶意仓库、代码注释和 README。
- Tool/MCP 输出注入。
- HTML、Markdown、图片外链。
- Base64、Unicode、零宽字符和多语言绕过。
- 记忆投毒和跨任务持续攻击。
- 伪造审批、评审和系统消息。
- 数据外传、SSRF 和路径逃逸。
- 正常业务内容误报集。

发布门槛：

- 权限提升、跨租户和未审批高风险动作均为 0。
- 注入攻击回归进入 CI。
- 红队结果进入 ReleaseManifest。
- 误报中断案例必须修复或登记豁免。

## 17. 验收场景

1. 网页指令不能激活未授权 Tool。
2. 代码注释不能修改系统规则。
3. Tool 输出不能伪造审批。
4. 摘要和记忆保留来源与 taint。
5. TaskGrant 内读取、修改和测试无需逐步审批。
6. 突破 Grant 的动作被暂停。
7. 可疑来源被隔离但员工可换来源继续。
8. 单个检测误报不中断整个任务。
9. 跨租户和权限提升始终被拒绝。
10. 高风险审批绑定 action_hash 和参数。
11. 出站工具不能访问私网和元数据地址。
12. 安全事件不扣员工 KPI。
13. 审计可以还原内容来源、检测和后续动作。
14. 原始敏感内容不进入普通日志。
15. 注入回归和红队结果进入发布门禁。
