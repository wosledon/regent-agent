# 42 内部 API 与扩展边界

- 版本：v0.1（待评审）
- 范围：内部 API、Tool、内部 MCP、租户内部扩展和公共生态边界
- 对应需求：FR-086、BR-145、BR-146、BR-147
- 对应缺口：G-57

## 1. 当前范围

- `/v1` 只作为系统内部 API。
- Tool 以 `ToolManifest + AIFunction` 为主。
- MCP 只保留内部工具面：
  - Butler 只读工具。
  - 模型评测工具。
- 租户内部 Tool、Skill 和依赖按 Q-021 审核、签名和撤销。

当前不提供：

- 公共 REST API。
- 对外 API Token 或 OAuth Client。
- 公共 SDK。
- 出站 Webhook。
- MCP 市场。
- 插件市场或发布者后台。
- 跨租户 Skill 分享。
- 第三方插件自动安装和更新。

## 2. 内部 API 边界

- `/v1` 服务仪表盘、ControlPlane、Gateway、Runner 和运营平台。
- 内部 API 使用现有会话、服务身份、assignment token 和 SupportGrant。
- 不新增公共 API 认证主体。
- 不把内部错误模型、分页、幂等或状态机承诺为公共兼容契约。
- 外部网络访问内部管理端点默认拒绝。
- 自托管部署也不因此开放公共 API。

## 3. Tool 边界

- 只能加载已注册 ToolManifest。
- Tool Schema 和权限随版本固定。
- 每次调用由执行层重新鉴权。
- 写 Tool 必须有幂等键和审计。
- 已批准 Tool 可自主调用，安装、升级、扩权仍须审核。
- 普通员工不能自行注册生产 Tool。

## 4. MCP 边界

- MCP 当前只用于内部 Butler 只读工具和模型评测工具面。
- 不作为通用员工插件协议。
- 不提供公共 MCP Server 注册、发现市场或远程目录。
- MCP Server 不能自行注册 Tool 或扩大权限。
- 新 Tool 默认禁用，必须重新审批。
- 在途 TaskRun 不中途升级 MCP 或 Tool。

## 5. 租户内部扩展

- 租户可以创建内部 Skill、Tool 包和依赖清单。
- 内部扩展仍登记为 SupplyChainArtifact。
- 必须具有版本、digest、签名、SBOM、许可和准入记录。
- 生产禁止未签名制品和 `latest`。
- 撤销按 digest 传播并保留影响分析。
- 内部扩展不自动跨租户共享，也不进入公共市场。

## 6. 供应链审核

沿用 Q-021：

```text
提交制品
  → 签名验证
  → digest 固定
  → SBOM
  → 漏洞和许可扫描
  → 权限、网络和文件系统审查
  → 隔离试运行
  → 审批或拒绝
```

- 审核的是不可变制品，不是发布者名称。
- 发布者声誉不能替代审核。
- 外部第三方制品的公共分发当前不做，但租户显式导入仍按同一准入规则。
- 不提供自动更新、自动安装或市场评分。

## 7. 安全边界

- 内部 API 不因路径含 `/v1` 而降低鉴权要求。
- 外部调用不能借用员工令牌或服务令牌。
- MCP 和插件输出仍是不可信内容，保留来源和 taint。
- 插件声明不是授权，Tool Call 必须再次鉴权。
- 插件不得访问模型密钥、其他租户数据或未授权网络。
- 公共生态相关端点当前不创建，也不保留空壳兼容层。

## 8. 版本与兼容

- 内部 API 可随系统版本演进。
- 不发布公共 SemVer、弃用周期或 SDK 兼容承诺。
- Tool、MCP 和 Skill 的制品版本仍不可变。
- TaskRun 固定实际加载的制品 digest。
- 回滚恢复旧 digest，不覆盖历史。

## 9. 实体

- `InternalApiClient`：服务或内部调用身份，不是公共 OAuth Client。
- `ToolManifest`：内部 Tool Schema 和权限。
- `McpToolSurface`：Butler 或模型评测的内部工具面。
- `SupplyChainArtifact`：租户内部扩展制品。
- `AdmissionReview`：制品准入审核。

## 10. 指标

| 指标 | 目标 |
|---|---:|
| 公共 API 端点数量 | 0 |
| 公共 SDK 数量 | 0 |
| 出站 Webhook 数量 | 0 |
| 市场或跨租户发布次数 | 0 |
| 未批准生产 Tool 加载数 | 0 |
| 未登记第三方制品加载数 | 0 |

## 11. 测试场景

1. 外部请求访问内部 `/v1` 管理端点被拒绝。
2. 不存在公共 API Token 或 OAuth Client 创建流程。
3. 不生成公共 SDK 包。
4. 不创建出站 Webhook 端点。
5. 不提供 MCP 或插件市场接口。
6. Butler MCP 工具面保持只读。
7. 模型评测 MCP 工具面只允许授权岗位。
8. 普通员工不能注册生产 Tool。
9. 未登记第三方制品无法加载。
10. 未签名制品无法进入生产。
11. MCP 新增 Tool 默认禁用。
12. 插件输出保留 taint，不能提升权限。
13. TaskRun 不中途升级制品。
14. 租户内部扩展不会自动跨租户共享。
15. 撤销后所有实例拒绝新调用。

## 12. 验收场景

1. 当前只有内部 API、Tool 和内部 MCP 工具面。
2. 不提供公共 API、SDK、Webhook 或市场。
3. 内部 API 不构成公共兼容承诺。
4. 租户内部扩展仍受 Q-021 完整准入和撤销约束。
5. 不保留公共生态空壳接口或自动安装更新能力。
